# D1 — 倒排索引：为什么搜"批量"能秒找到 100 条笔记？

> **定位**：es-lab 第 1 篇。Elasticsearch 的地基——**倒排索引**。
> **对照**：xhs-project `my-xhs-search`（ES 8.12.2）；本 lab 本地单节点 ES 实测。

---

## 一、它干了什么：一个例子

库里有 100 条"批量笔记 N"，搜 `title=批量`：

```bash
curl -G --data-urlencode "q=批量" http://127.0.0.1:28060/a03/match
# {"total":100,"returned":5,"titles":["批量笔记 1","批量笔记 2",...]}
```

**100 条秒出**——对比 MySQL `LIKE '%批量%'` 全表扫描（100 万条就卡了）。

**它干了什么一句话**：ES 把文档**预先切成词项（term）**，建立"**词项 → 文档 ID 列表**"的映射表（倒排索引）——搜索 = 查词项拿列表，而不是扫全表。

```
正向（文档 → 词）:  笔记1: [批量, 笔记, 1]   笔记2: [批量, 笔记, 2]
倒排（词 → 文档）:  批量 → [1, 2, 3, ... 100]   笔记 → [1, 2, ...]
                    ↑ 搜索"批量"直接取这个列表
```

---

## 二、为什么需要它：MySQL 的两个不够用

| 需求 | MySQL | ES |
|---|---|---|
| 全文检索（分词、相关性排序） | `LIKE '%x%'` 无法用索引（左模糊）；全文索引功能弱 | 倒排 + 分词 + TF-IDF/BM25 打分 |
| 海量数据多条件筛选+排序+聚合 | 大表多条件组合索引爆炸 | 倒排 + doc_values 列存，组合自由 |

xhs 的搜索场景（笔记标题/内容/标签检索 + 召回排序）就是典型：DB 是"事实源"，ES 是"检索副本"（回链 D5 同步）。

## 三、怎么做：分词 → 词项 → 倒排

### 3.1 第一步：分词（analyze 实测）

```bash
curl -G --data-urlencode "text=小红书种草笔记" http://127.0.0.1:28060/a01/analyze
# {"tokens":["小","红","书","种","草","笔","记"]}
```

**关键发现**：`standard` 分词器对中文**按单字切分**——所以搜索"笔记"能匹配（"笔"+"记"两个 token 都命中）。
生产（xhs）用 **IK 分词器**（`ik_smart`/`ik_max_word`）：`小红书种草笔记` → `[小红书, 种草, 笔记]`——词项粒度更合理、召回更准。

### 3.2 第二步：倒排表（term → posting list）

每个字段的每个词项维护一个 posting list（文档 ID + 词频 + 位置）：
- **词频**：算相关性（BM25）
- **位置**：支持短语查询（"笔记 批量"相邻）

### 3.3 第三步：查询 = 查倒排 + 打分排序

`match` 查询把输入分词 → 每个词项查倒排 → 合并（OR/AND）→ BM25 打分 → 排序返回。

## 四、坑与边界

| 坑 | 说明 |
|---|---|
| 中文默认按字切 | standard 分词中文效果差——生产必须 IK（或同义词/自定义词典） |
| 分词不可逆 | 索引时怎么切，查询时也怎么切——**索引和查询的 analyzer 必须一致** |
| 倒排只服务"词项匹配" | 范围/排序/聚合靠 doc_values（列存）——D3 展开 |
| ES 不是数据库 | 无事务、近实时（D4）、要同步（D5）——"事实源"永远在 DB |

## 六、值不值得深挖 & 面试问答

**值不值得**：🔴 必问——"ES 为什么快/倒排索引是什么"是 ES 面试第一题；分词（中文按字 vs IK）是高频追问。

**Q1：倒排索引和 B+树索引的区别？**
B+树服务"范围/等值查询"（有序结构）；倒排服务"文本检索"（词项→文档映射 + 打分）。ES 两者都有：倒排做检索、doc_values 做排序聚合。

**Q2：为什么 ES 搜中文效果差？**
默认 standard 分词器按单字切——需要 IK 分词器（词典驱动）；xhs 生产用 IK（回链 D2）。

**Q3：ES 和 MySQL 全文索引怎么选？**
数据量小、事务内 → MySQL 全文索引；海量、复杂检索/聚合/相关性 → ES（接受同步延迟）。
