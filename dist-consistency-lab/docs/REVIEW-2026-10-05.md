# dist-consistency-lab 建设与验证记录（2026-10-05）

> 背景：L2-3 一致性模式单元——**新建 lab**（非迁移）。把 xhs-project 的四个生产模式抽成最小对照实现 + 实验端点。
> 设计基线：**xhs-project 真实实现**（MessageIdempotentHelper / Coupon·Inventory Outbox / *ReconcileJob / RetryBackoffUtils）。
> 运行环境：**自包含**（本地 Redis 127.0.0.1:6379 + H2 内存库 + FakeMqBroker）——不依赖外部中间件。

## 二、端到端验证（全部实测通过）

**单测**：6/6（`RetryBackoffUtilsTest` 3 + `IdempotentHelperTest` 3——含"Redis 降级放行"用例）

**A01 幂等**（curl 实测）：
- m1 首次 → 余额 1010；m1 重复 → "重复消息已忽略（SETNX 拦截）"（余额不变）✓
- m2 failFirst → removeMark → 重试成功（1020）✓

**A02 Outbox**（curl 实测）：
- 注入 Broker 故障 → 下单：DB 事务成功、即时投递失败（余额已扣 1015）✓
- 补发（仍故障）→ retry_count=1、next_retry≈+33s（退避）✓
- 恢复 Broker → 补发 force → 投递成功、Broker 收到消息 ✓（attemptLog 完整记录失败→恢复→成功链）

**A03 对账**（curl 实测）：
- 扣 7 只写 Redis → diff=7、consistent=false ✓
- reconcile → 以 Redis 为准修复 → diff=0、consistent=true ✓

**A04 补偿重试**（curl 实测）：
- 退避序列 `[31, 51, 104, 230, 467, 503, 455, 576]`（指数+封顶+抖动）✓
- 重试链 → 死信终态（deadLetterCount=1）✓

## 三、设计口径

1. **自包含优先**：FakeMqBroker 替代真实 MQ（可注入故障）——实验聚焦模式本身，不引入外部依赖；
2. **权威源按域定**（D3）：本 lab 演示"Redis 为准"（库存口径）；文档明确其他域相反口径；
3. **与 xhs-project 同构**：核心算法（SETNX/removeMark/退避/补发状态机）逐字对齐，规模最小化；
4. 实验端点带 `force`/`reset` 等实验便利参数，不影响模式语义。

## 五、边界

- FakeMqBroker 为内存实现（重启即清空）——真实 MQ 的堆积/顺序/DLQ 语义见 RocketMQ 系列；
- 对账/补发未接真实调度（XXL-Job）——周期调度语义以文档对照为准；
- H2 内存库重启清空——演示用；生产为 MySQL（xhs）。
