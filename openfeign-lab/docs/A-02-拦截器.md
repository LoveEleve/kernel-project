# A-02: 请求拦截器

## 一、场景

每个 Feign 请求都需要透传一些 Header,例如:
- **追踪 ID**: 一次调用链的所有请求带同一个 traceId,用于日志串联
- **认证 Token**: 调用下游服务时携带 JWT Token
- **灰度标识**: 标记请求来自哪个版本,用于灰度路由
- **调用方标识**: 被调方根据调用方来源做不同的处理

如果每个方法都手动加 Header,代码会严重重复:

```java
// 反模式: 每个 Feign 方法都手动加 Header
@PostMapping("/order/create")
String createOrder(@RequestHeader("X-Trace-Id") String traceId, @RequestBody Order order);

@GetMapping("/order/{id}")
String getOrder(@RequestHeader("X-Trace-Id") String traceId, @PathVariable Long id);
```

OpenFeign 的 **RequestInterceptor** 可以统一拦截所有 Feign 请求,自动注入 Header。

## 二、实现

### 2.1 自定义拦截器

```java
@Component
public class TraceIdInterceptor implements RequestInterceptor {

    private static final String TRACE_ID_HEADER = "X-Trace-Id";

    @Override
    public void apply(RequestTemplate template) {
        // 优先使用 MDC 中的 traceId(外部链入)
        String traceId = MDC.get(TRACE_ID_HEADER);
        if (traceId == null || traceId.isEmpty()) {
            traceId = UUID.randomUUID().toString().replace("-", "");
        }
        template.header(TRACE_ID_HEADER, traceId);

        // 同时注入调用方服务名(灰度发布等场景可用)
        template.header("X-Source-App", "openfeign-lab");

        log.debug("[FeignInterceptor] 注入 Header: {}={}, 请求路径: {}",
                TRACE_ID_HEADER, traceId, template.path());
    }
}
```

**关键点**:
- `implements RequestInterceptor` + `@Component` -- Spring 自动发现并注册到 Feign
- `template.header(key, value)` -- 注入 Header,每个 Feign 请求都会携带
- MDC -> UUID 降级 -- 如果外部已有 traceId(MDC 传入),沿用;否则自生成

### 2.2 验证方式

openfeign-lab 调用 nacos-lab 的 `/echo/headers` 端點,nacos-lab 把收到的 Header 回显。通过对比回显的 Header 值,确认拦截器是否生效:

```
curl http://localhost:28002/feign/interceptor-test
  -> Feign NacosLabClient.echoHeaders()
  -> TraceIdInterceptor.apply() 注入 X-Trace-Id + X-Source-App
  -> HTTP GET http://nacos-lab/echo/headers (携带这两个 Header)
  -> nacos-lab 回显收到的 Header
  -> openfeign-lab 对比回显的值
```

## 四、多个拦截器的执行顺序

如果有多个拦截器,按以下顺序执行:

1. `@Order(100)` 优先级高的先执行
2. 同优先级按类名排序

```java
@Order(1)  // 先执行: 认证 Token
public class AuthInterceptor implements RequestInterceptor {
    public void apply(RequestTemplate t) {
        t.header("Authorization", "Bearer " + getToken());
    }
}

@Order(2)  // 后执行: 追踪 ID
public class TraceIdInterceptor implements RequestInterceptor {
    public void apply(RequestTemplate t) {
        t.header("X-Trace-Id", getTraceId());
    }
}
```

多个拦截器形成**装饰器链**: `AuthInterceptor.apply` -> `TraceIdInterceptor.apply` -> Feign 发送请求。

## 五、生产注意

- **`@Component` 自动生效**: `RequestInterceptor` 接口的 Spring Bean 会自动被 Feign 使用,不需要额外配置。添加 `@Component` 即可,对 Feign 全局生效
- **粒度控制**: 如果只想对特定 `@FeignClient` 生效,用 `@Configuration` + `@Bean` + 指定 `contextId`。默认对所有 Feign 客户端生效
- **MDC 集成**: 生产应该用日志框架的 MDC 传递 traceId,和日志链路打通。本 lab 用的 `UUID.randomUUID()` 是简化版
- **不要在拦截器里做网络 IO**: `RequestInterceptor.apply()` 在 Feign 的调用线程同步执行,如果在这里面做 HTTP 调用或数据库查询,会阻塞所有 Feign 请求
