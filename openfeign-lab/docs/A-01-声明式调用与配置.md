# A-01: 声明式调用与配置

## 一、什么是声明式调用

传统 HTTP 客户端(RestTemplate/RestClient)需要手写 URL 拼接、参数编码、响应解析:

```java
// RestTemplate 方式 -- 手写一切
String url = "http://localhost:28001/discovery/status?serviceName=nacos-lab";
ResponseEntity<String> resp = restTemplate.getForEntity(url, String.class);
String body = resp.getBody();
// 还要手动 JSON 解析...
```

OpenFeign 的做法: **定义一个 Java 接口,加几个注解,剩下的交给框架**:

```java
@FeignClient(name = "nacos-lab")
public interface NacosLabClient {

    @GetMapping("/health")
    String health();

    @GetMapping("/discovery/status")
    Map<String, Object> discoveryStatus();
}
```

调用时就像调本地方法:
```java
@Autowired
private NacosLabClient nacosLabClient;

String result = nacosLabClient.health();
// Feign -> LoadBalancer -> Nacos 服务发现 -> nacos-lab(ip:port) -> HTTP GET /health
```

**Feign 帮你做的事**: URL 拼接、参数编码、HTTP 请求发送、响应反序列化、错误处理。你只写接口签名。

## 二、@FeignClient 核心配置

### 2.1 name + 服务发现

```java
@FeignClient(name = "nacos-lab")
```

| 属性 | 作用 | 示例 |
|------|------|------|
| `name` | Feign 客户端名称,也是调用的服务名 | `"nacos-lab"` |
| `url` | 直接指定地址(不设 = 走服务发现) | 不设 |
| `contextId` | Bean 唯一标识(多个 FeignClient 指向同一 name 时用) | `"nacos-lab-v1"` |
| `path` | 统一路径前缀 | `"/api/v1"` |

**name + 服务发现的工作方式**:

不设 `url`,Feign 用 `name="nacos-lab"` 作为服务名,通过 Nacos 服务发现获取实例地址:

```
@FeignClient(name = "nacos-lab")
  -> FeignBlockingLoadBalancerClient 拦截请求
  -> LoadBalancerClient.choose("nacos-lab")
  -> Nacos 服务发现: 返回 nacos-lab 的一个实例(ip:port)
  -> 替换 URL: http://nacos-lab/health -> http://21.214.97.212:28001/health
  -> 发送真正的 HTTP 请求
```

**三种组合**:

| 场景 | name | url | 行为 |
|------|------|-----|------|
| 服务发现(推荐) | 服务名(与注册中心一致) | 不设 | 从 Nacos 获取实例,LoadBalancer 选择 |
| 直连调试 | 任意 | `http://host:port` | 绕过服务发现,直接请求指定 URL |
| 服务发现 + 覆盖 URL | 服务名 | `http://...` | 用 name 做 Bean 标识,但实际请求 url |

### 2.2 接口方法与 HTTP 映射

OpenFeign 用 Spring MVC 注解做 HTTP 映射:

```java
@FeignClient(name = "nacos-lab")
public interface NacosLabClient {

    @GetMapping("/health")
    String health();                    // GET -> 返回 String

    @GetMapping("/discovery/status")
    Map<String, Object> discoveryStatus();  // GET -> 返回 Map(自动 JSON 反序列化)

    @GetMapping("/config/history")
    Map<String, Object> configHistory();    // GET -> 返回 Map

    @PostMapping("/discovery/set-unhealthy")
    Map<String, Object> setUnhealthy();     // POST -> 返回 Map

    @GetMapping("/lb/instances")
    String lbInstances();                   // GET -> 返回 String
}
```

**映射规则**(SpringMvcContract 解析):

| Java 注解 | HTTP 方法 | 参数位置 |
|-----------|----------|---------|
| `@GetMapping("/path")` | GET | 路径 |
| `@PostMapping("/path")` | POST | 路径 |
| `@RequestParam("key")` | - | Query 参数 `?key=value` |
| `@RequestHeader("key")` | - | Header |
| `@RequestBody` | - | Body(POST/PUT) |
| `@PathVariable("id")` | - | 路径变量 `/path/{id}` |

**返回值自动反序列化**:
- `String` -> 原始响应体
- `Map<String, Object>` -> JSON 自动解析为 Map
- 自定义 POJO -> JSON 自动映射到对象字段

## 三、本 lab 的调用架构

```
curl http://localhost:28002/feign/health
       |
       v
+------------------+          +-------+          +------------------+
| openfeign-lab    |  Feign   | Nacos  |  实例    | nacos-lab        |
| (port 28002)     | -------> |服务发现 | ------> | (port 28001)     |
|                  | http://  |        | ip:port |                  |
| FeignTestCtrl    | nacos-lab|        |         | RegistrationCtrl |
|  -> NacosLabClient|  /health|        |         |  -> "running"    |
+------------------+          +-------+          +------------------+
```

1. curl 请求 openfeign-lab 的 `/feign/health`
2. FeignTestController 调用 `nacosLabClient.health()`
3. Feign 发现没有 `url`,用 `FeignBlockingLoadBalancerClient` 拦截请求
4. LoadBalancer 通过 Nacos 服务发现获取 `nacos-lab` 的一个实例(`21.214.97.212:28001`)
5. Feign 发送 HTTP GET 到 `http://21.214.97.212:28001/health`
6. nacos-lab 返回 `"nacos-lab is running"`
7. Feign 反序列化为 String 返回给调用方

### 服务发现配置

openfeign-lab 也注册到同一个 Nacos 集群,这样才能发现 nacos-lab:

```yaml
spring:
  cloud:
    nacos:
      discovery:
        server-addr: 21.130.247.89:18848
        namespace: sca-lab-dev
```

**openfeign-lab 注册到 Nacos 不是为了被调用(它没有别的服务要调它),而是为了访问 Nacos 的服务发现功能**。只有注册到 Nacos 的客户端才能查询服务列表。

## 五、关键设计点

### 为什么 Feign 接口不需要 @Component

`@FeignClient` 本身就是一个复合注解,Spring Cloud OpenFeign 通过 `FeignClientsRegistrar`(D-05 源码)扫描 `@FeignClient` 注解的接口,为每个接口创建一个 FactoryBean,最终生成 JDK 动态代理注入到 Spring 容器。不需要额外加 `@Component`。

### 为什么返回 Map 而不是自定义 POJO

本 lab 的 NacosLabClient 返回 `Map<String, Object>` 而不是自定义 POJO,因为:
- nacos-lab 的返回结构可能变化(不同端点返回不同字段)
- Map 更灵活,不需要为每个端点定义 DTO
- 教学场景: 重点是 Feign 的调用机制,不是数据建模

**生产环境应该用 POJO**: 定义 `NacosLabStatusVO` 等类,享受编译期类型检查 + IDE 自动补全。

### name 与 LoadBalancer 的协作

`name="nacos-lab"` 在这个 Feign 客户端中承担双重角色:
- Bean 命名: 默认 Bean 名 = name 值(首字母小写)
- 服务发现: LoadBalancer 用这个 name 去 Nacos 查实例列表

两者缺一不可: 只有 name 没有 LoadBalancer -> DNS 解析失败("Temporary failure in name resolution"); 有 LoadBalancer 但没有 name -> LoadBalancer 不知道查哪个服务。

## 六、生产注意

- **服务发现优先于 url 直连**: 本 lab 用 `name` + LoadBalancer + Nacos 服务发现,这是生产推荐方式。`url` 直连只适合调试或调用不注册到注册中心的外部服务
- **LoadBalancer 不可少**: 用 `name` 服务发现时,必须保证 `spring-cloud-starter-loadbalancer` 在 classpath 上,且 `spring.cloud.loadbalancer.enabled=true`(默认)。否则 Feign 无法解析服务名
- **注册到 Nacos 才能发现别人**: openfeign-lab 自己也注册到了 Nacos,不是为了被调用,而是为了能查询到 nacos-lab 的实例列表。如果不注册,`DiscoveryClient.getInstances("nacos-lab")` 返回空
- **超时未配置**: 当前使用 Feign 默认超时。A-03 会深入超时配置
- **无熔断**: 当前调用失败直接抛异常。A-06 会加 Sentinel 熔断
- **无拦截器**: 当前请求不带任何自定义 Header。A-02 会加 RequestInterceptor
