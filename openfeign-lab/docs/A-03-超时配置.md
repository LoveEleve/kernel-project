# A-03: 超时配置

## 一、Feign 超时配置

OpenFeign 支持两种超时:
- **connectTimeout**: 建立连接的超时(默认 10s)
- **readTimeout**: 等待响应的超时(默认 60s)

通过配置文件设置:

```yaml
# 全局默认(对所有 FeignClient 生效)
spring.cloud.openfeign.client.config.default.connectTimeout: 5000
spring.cloud.openfeign.client.config.default.readTimeout: 5000

# 特定 client(nacos-lab-direct)
spring.cloud.openfeign.client.config.nacos-lab-direct.connectTimeout: 2000
spring.cloud.openfeign.client.config.nacos-lab-direct.readTimeout: 2000
```

`nacos-lab-direct` 对应 `@FeignClient(name = "nacos-lab-direct")` 的 name 属性。

## 二、测试: 2s 超时 vs 1s/3s 请求

openfeign-lab 有一个直接 URL 指向 nacos-lab 的客户端:

```java
@FeignClient(name = "nacos-lab-direct", url = "http://localhost:28001")
public interface NacosLabDirectClient {
    @GetMapping("/echo/slow")
    Map<String, Object> echoSlow(@RequestParam("seconds") int seconds);
}
```

nacos-lab 的 `/echo/slow` 端点会 sleep 指定秒数再返回。用 Feign 调这个端点,分别在 1s(小于超时)和 3s(大于超时)下测试。

## 三、验证

```
curl http://localhost:28002/feign/timeout-test?seconds=1
curl http://localhost:28002/feign/timeout-test?seconds=3
```

### 实际结果

**1s 请求(应成功)**:
```json
{
    "success": true,
    "costMs": 1051,
    "readTimeout": "2000ms",
    "responseSleepSeconds": 1,
    "responseActualCostMs": 1000
}
```
- Feign 等待 1s,收到正常响应 ✅

**3s 请求(应超时)**:
```json
{
    "success": false,
    "costMs": 2004,
    "readTimeout": "2000ms",
    "error": "RetryableException: Read timed out executing GET ..."
}
```
- Feign 在 2004ms 时报 `Read timed out` -- 正好在 2000ms 超时阈值触发 ✅
- 如果不是超时配置,默认会等 60s 才断开

### 关键观察

- `costMs: 2004` 对比 `error time: 3s+`: 超时在 2s 准时触发,没有等到请求自然完成(3s)
- readTimeout 控制的是**请求等待响应的总时间**,不是"每个字节"的超时

## 四、超时配置层级

Spring Cloud 中 Feign 超时可能受多层影响:

```
Feign readTimeout(2s)
  -> 实际由底层 HTTP Client 执行
    -> HttpURLConnection: 默认 readTimeout=infinity
    -> Apache HttpClient5: 默认 readTimeout=60s
    -> OkHttp: 默认 readTimeout=10s
  -> LoadBalancer 实例选择超时(如果有负载均衡)
```

如果用了 LoadBalancer(`name` 不带 `url`),请求分两步:
1. **LoadBalancer 选实例**: 从 Nacos 获取服务列表 + 选择实例(默认超时由 `LoadBalancerClientFactory` 控制,通常是几秒)
2. **Feign 发请求**: 用选中的实例地址替换 `http://服务名/...` -> 发送真正的 HTTP 请求(受 `readTimeout`/`connectTimeout` 控制)

**两者是串联关系,不是叠加**: LoadBalancer 选实例超时了,Feign 连请求都没发出去。选实例成功后才到 Feign 的超时控制。本 lab 用 `url` 直连完全绕过了 LoadBalancer 层,确保测试的是 Feign 自身的超时。

## 五、生产注意

- **readTimeout 不应设太大**: 默认 60s 太长,分布式环境下一个请求等 60s 会耗尽线程池。推荐 3-10s
- **connectTimeout 应该设小**: 连接失败说明网络或服务有问题,不应该久等。推荐 1-3s
- **超时和重试配合**: 超时触发后配合 circuit breaker 熔断(A-06),避免重试放大压力

## 六、为什么用 `nacos-lab-direct`(带 url)而不是 `nacos-lab`(服务发现)

nacos-lab 排除自动注册(`exclude = NacosServiceRegistryAutoConfiguration`)。所以 LoadBalancer 无法从 Nacos 获取它的实例。为了测试超时,这里用 `url` 直连。

这不影响 A-01 声明式调用的测试结果(A-01 在 nacos-lab 运行时调通了)。
