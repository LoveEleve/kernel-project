# A-07: 负载均衡

## 一、Feign + LoadBalancer 负载均衡原理

Spring Cloud OpenFeign 通过 `@FeignClient(name = "nacos-lab")` 使用服务名调用时,自动集成 `Spring Cloud LoadBalancer` 进行客户端负载均衡。

### 调用链路

```
Feign Client (openfeign-lab)
    │
    │  @FeignClient(name = "nacos-lab")
    │  GET /discovery/status
    │
    ▼
FeignBlockingLoadBalancerClient
    │
    ├── NacosDiscoveryClient.getInstances("nacos-lab")
    │       → 从 Nacos Server 拉取实例列表
    │       → [{host: localhost, port: 28001}, {host: localhost, port: 28003}]
    │
    ├── LoadBalancer.choose()
    │       → 轮询(RoundRobin)选择一个实例
    │
    └── 发送 HTTP 请求到选中实例
```

### 关键组件

| 组件 | 角色 |
|------|------|
| `FeignBlockingLoadBalancerClient` | Feign 负载均衡客户端包装器,拦截服务名调用 |
| `NacosDiscoveryClient` | 从 Nacos 获取服务实例列表 |
| `LoadBalancer` (RoundRobin) | 默认轮询策略,依次选择实例 |

## 二、启动多实例

A-07 需要至少 2 个 nacos-lab 实例注册到 Nacos。

### 实例 1 (默认端口 28001)

```bash
mvn spring-boot:run -pl nacos-lab -q > /tmp/nacos-lab1.log 2>&1 &
```

### 实例 2 (端口 28003)

```bash
mvn spring-boot:run -pl nacos-lab -q \
  -Dspring-boot.run.profiles=instance2 > /tmp/nacos-lab2.log 2>&1 &
```

`application-instance2.yml`:

```yaml
server:
  port: 28003
```

Spring Boot 根据 `spring-boot.run.profiles=instance2` 加载此配置覆盖端口。两个实例会自动注册到 Nacos。

### 验证注册

```bash
# 查看所有 nacos-lab 实例
curl http://localhost:28001/lb/instances

# 在 openfeign-lab 中查看发现的服务
curl http://localhost:28002/feign/client-info
```

## 三、验证负载均衡

### 测试端点

```
GET /feign/load-balance-test
```

调用 nacos-lab 的 `/discovery/status` 端点 20 次,每次返回处理请求的实例端口。LoadBalancer 轮询分发,两次请求应落到不同实例。

### 预期结果

```json
{
    "test": "A7-负载均衡",
    "totalCalls": 20,
    "portDistribution": {
        "28001": 10,
        "28003": 10
    },
    "calls": [
        {"call": 1, "success": true, "port": 28001, "costMs": 5},
        {"call": 2, "success": true, "port": 28003, "costMs": 4},
        {"call": 3, "success": true, "port": 28001, "costMs": 3},
        ...
    ]
}
```

- `portDistribution` — 两个实例各约 10 次(轮询均匀分布)
- `calls[].port` — 每次请求实际处理的服务端口

## 四、LoadBalancer 配置

### 切换负载均衡策略

```yaml
spring.cloud.loadbalancer.configurations: random   # 随机策略
# 或保留默认轮询:
# spring.cloud.loadbalancer.configurations: round-robin
```

Spring Cloud LoadBalancer 支持:

| 策略 | 值 | 说明 |
|------|-----|------|
| 轮询 | `round-robin` | 默认,依次选择 |
| 随机 | `random` | 随机选择 |
| 健康检查 | `health-check` | 结合 HealthCheckServiceInstanceListSupplier 过滤不健康的实例 |
| 自定义 | `@Bean LoadBalancer` | 实现自定义策略 |

### 自定义策略示例

```java
@Bean
public ReactorLoadBalancer<ServiceInstance> randomLoadBalancer(
        Environment environment, LoadBalancerClientFactory loadBalancerClientFactory) {
    String name = environment.getProperty(LoadBalancerClientFactory.PROPERTY_NAME);
    return new RandomLoadBalancer(
            loadBalancerClientFactory.getLazyProvider(name, ServiceInstanceListSupplier.class), name);
}
```

## 五、FeignBlockingLoadBalancerClient 源码要点

核心逻辑（4.1.3:105-136 全文）。同步阻塞来自 `LoadBalancerClient.choose(serviceId, lbRequest)`（阻塞门面）；Reactor 版 `ReactorLoadBalancer` 返回 `Mono`，由阻塞门面内部取值：

```java
@Override
public Response execute(Request request, Request.Options options) throws IOException {
    final URI originalUri = URI.create(request.url());
    String serviceId = originalUri.getHost();
    Assert.state(serviceId != null, "Request URI does not contain a valid hostname: " + originalUri);
    String hint = getHint(serviceId);
    DefaultRequest<RequestDataContext> lbRequest = new DefaultRequest<>(
            new RequestDataContext(buildRequestData(request), hint));
    Set<LoadBalancerLifecycle> supportedLifecycleProcessors = LoadBalancerLifecycleValidator
            .getSupportedLifecycleProcessors(
                    loadBalancerClientFactory.getInstances(serviceId, LoadBalancerLifecycle.class),
                    RequestDataContext.class, ResponseData.class, ServiceInstance.class);
    supportedLifecycleProcessors.forEach(lifecycle -> lifecycle.onStart(lbRequest));
    ServiceInstance instance = loadBalancerClient.choose(serviceId, lbRequest);
    org.springframework.cloud.client.loadbalancer.Response<ServiceInstance> lbResponse = new DefaultResponse(
            instance);
    if (instance == null) {
        String message = "Load balancer does not contain an instance for the service " + serviceId;
        if (LOG.isWarnEnabled()) {
            LOG.warn(message);
        }
        supportedLifecycleProcessors.forEach(lifecycle -> lifecycle
                .onComplete(new CompletionContext<ResponseData, ServiceInstance, RequestDataContext>(
                        CompletionContext.Status.DISCARD, lbRequest, lbResponse)));
        return Response.builder().request(request).status(HttpStatus.SERVICE_UNAVAILABLE.value())
                .body(message, StandardCharsets.UTF_8).build();
    }
    String reconstructedUrl = loadBalancerClient.reconstructURI(instance, originalUri).toString();
    Request newRequest = buildRequest(request, reconstructedUrl, instance);
    return executeWithLoadBalancerLifecycleProcessing(delegate, options, newRequest, lbRequest, lbResponse,
            supportedLifecycleProcessors);
}
```

## 六、生产注意

- **健康检查**: `FeignBlockingLoadBalancerClient` 依赖于 `DiscoveryClient` 返回的实例列表。如果实例不健康,Nacos 会自动摘除
- **缓存**: Nacos 客户端本地缓存服务实例列表,默认 10 秒刷新。可通过 `spring.cloud.nacos.discovery.watch.enabled=true` 开启 watch 推送
- **同机房优先**: Nacos 支持根据 `clusterName` 优先调用同集群实例。结合 LoadBalancer 可实现同机房路由
- **重试**: LoadBalancer 不自动重试。如需失败重试,可配合 `spring-retry` + `@RetryableConfig`
