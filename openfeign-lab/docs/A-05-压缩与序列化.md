# A-05: 压缩与序列化

## 一、压缩的作用

HTTP 压缩减少传输数据量,降低网络延迟。对于 JSON 这类文本协议,压缩率可达 5-10 倍。

Spring Cloud OpenFeign 的压缩分两个方向:

| 方向 | 配置 | 机制 |
|------|------|------|
| 请求压缩(Client → Server) | `spring.cloud.openfeign.compression.request.*` | 拦截器设置 `Content-Encoding: gzip`,由 HTTP 客户端执行压缩 |
| 响应压缩(Server → Client) | `spring.cloud.openfeign.compression.response.*` + `server.compression.*` | 拦截器设置 `Accept-Encoding: gzip`,服务端压缩后 HTTP 客户端自动解压 |

## 二、配置详解

### 2.1 配置属性

```yaml
server:
  compression:
    enabled: true                    # Spring Boot 启用服务端响应压缩
    mime-types: application/json,text/plain
    min-response-size: 1024          # 超过 1KB 的响应才压缩

spring:
  cloud:
    openfeign:
      compression:
        request:
          enabled: true
          mime-types: application/json,text/plain  # 匹配的 MIME 类型才添加 Content-Encoding
          min-request-size: 1024                    # 超过此大小的请求体才添加压缩头
        response:
          enabled: true                             # 添加 Accept-Encoding: gzip
```

### 2.2 两阶段架构:拦截器 + HTTP 客户端

Spring Cloud OpenFeign 的压缩是**两阶段设计**:

| 阶段 | 组件 | 作用 |
|------|------|------|
| 1. 拦截器 | `FeignContentGzipEncodingInterceptor` | 检查 Content-Type 和 Content-Length,条件满足时添加 `Content-Encoding: gzip` **头**(不压缩正文) |
| 2. HTTP 客户端 | `ApacheHttp5Client` / `HttpURLConnection` | 读取 `Content-Encoding: gzip` 头,实际压缩请求正文 |

**关键理解**: `FeignContentGzipEncodingInterceptor` **只设头,不压缩正文**。是否真正压缩取决于底层 HTTP 客户端是否支持自动 gzip 压缩。

### 2.3 请求压缩流程

```
Feign Client                         Server
   │                                      │
   │ POST /feign/compression/echo         │
   │ Content-Type: text/plain             │
   │                                      │
   │ ① SpringEncoder 序列化 body          │
   │ ② Interceptor 设置 Content-Encoding  │
   │    (仅设头,不压缩)                    │
   │ ③ HTTP 客户端发送请求                │
   │    (是否压缩取决于客户端实现)          │
   │ ────────────────────────────────────→ │
   │     Content-Encoding: gzip            │
   │     Body: [可能已压缩/未压缩]          │
   │                                      │ 接收原始字节,检测 Content-Encoding
   │                                      │ 用 GZIPInputStream 尝试解压
   │ ←──────────────────────────────────── │ 返回检测结果
```

### 2.4 响应压缩流程

```
Feign Client                         Server
   │                                      │
   │ GET /feign/compression/large-data    │
   │ Accept-Encoding: gzip ── 拦截器设置  │
   │ ────────────────────────────────────→│
   │                                      │ server.compression.enabled=true
   │                                      │ 响应体 > 1024B → 自动 Gzip 压缩
   │ ←────────────────────────────────────│ Content-Encoding: gzip
   │ HTTP 客户端透明解压                    │ Body: [gzip bytes]
   │ 客户端拿到原始 JSON                    │
```

## 三、验证

### 3.1 全量压缩测试

```
curl http://localhost:28002/feign/compression-test
```

预期结果:

```json
{
    "test": "A5-压缩与序列化",
    "requestCompressionHeaderSet": true,
    "requestBodyActuallyCompressed": true,
    "requestOriginalSize": 15982,
    "requestReceivedSize": 1580,
    "requestDecompressedLength": 15982,
    "responseCompression": true,
    "responseDataLength": 1950
}
```

- `requestCompressionHeaderSet: true` — `Content-Encoding: gzip` 头已设置(拦截器生效)
- `requestBodyActuallyCompressed: true` — 请求体被 feign-hc5 实际压缩
- `requestOriginalSize(15982) → requestReceivedSize(1580)` — 压缩率约 10:1
- `decompressedLength(15982) == originalSize` — 解压后内容完整无损
- `responseCompression: true` — 响应压缩生效

### 3.2 单独测试请求压缩

```
curl -X POST http://localhost:28002/feign/compression/echo \
  -H "Content-Type: text/plain" \
  --data-binary '{"data":"test payload for compression"}'
```

返回 `contentEncoding` 为 `null`(因为未超过 min-request-size)。

发送大请求体(> 1024 字节):

```
# 生成 2KB 数据
PAYLOAD=$(python3 -c "print('x' * 2048)")
curl -X POST http://localhost:28002/feign/compression/echo \
  -H "Content-Type: text/plain" \
  --data-binary "$PAYLOAD"
```

应返回 `contentEncoding: "gzip"`。

### 3.3 单独测试响应压缩

```
curl -H "Accept-Encoding: gzip" http://localhost:28002/feign/compression/large-data
```

响应会被 gzip 压缩(肉眼不可读),但 `curl` 会自动解压显示原始内容。也可加 `-w '%{size_download}'` 看压缩后的传输大小。

## 四、SpringEncoder/SpringDecoder 序列化

Spring Cloud OpenFeign 默认使用 `SpringEncoder` 和 `SpringDecoder` 替换 Feign 原生的编解码器。

```java
// FeignClientsConfiguration（4.1.3:103-114）
@Bean
@ConditionalOnMissingBean
public Decoder feignDecoder(ObjectProvider<HttpMessageConverterCustomizer> customizers) {
    return new OptionalDecoder(new ResponseEntityDecoder(new SpringDecoder(messageConverters, customizers)));
}

@Bean
@ConditionalOnMissingBean
@ConditionalOnMissingClass("org.springframework.data.domain.Pageable")
public Encoder feignEncoder(ObjectProvider<AbstractFormWriter> formWriterProvider,
        ObjectProvider<HttpMessageConverterCustomizer> customizers) {
    return springEncoder(formWriterProvider, encoderProperties, customizers);
}
```

`feignEncoder`/`feignDecoder` 是装配入口；真正的构造在私有辅助方法 `springEncoder(...)`（4.1.3:180-186，表单场景包一层 `SpringPojoFormEncoder`）。

`SpringEncoder` 利用 Spring 的 `HttpMessageConverter` 体系序列化请求体:

| 转换器 | 用途 | 默认 Content-Type |
|--------|------|-------------------|
| `MappingJackson2HttpMessageConverter` | JSON ↔ Java 对象 | `application/json` |
| `StringHttpMessageConverter` | 文本 | `text/plain` |
| `ByteArrayHttpMessageConverter` | 字节数组 | `application/octet-stream` |
| `FormHttpMessageConverter` | 表单 | `application/x-www-form-urlencoded` |

执行顺序:编码器先序列化对象 → 拦截器检查 Content-Type/Content-Length → 设置 Content-Encoding 头 → HTTP 客户端检查头 → 可选压缩正文。

## 五、源码分析

`FeignContentGzipEncodingInterceptor` 核心逻辑(`requiresCompression`):

```java
private boolean requiresCompression(RequestTemplate template) {
    final Map<String, Collection<String>> headers = template.headers();
    return matchesMimeType(headers.get(HttpEncoding.CONTENT_TYPE))
            && contentLengthExceedThreshold(headers.get(HttpEncoding.CONTENT_LENGTH));
}
```

它仅通过**头信息**决定是否添加 `Content-Encoding: gzip`,不操作正文。实际正文压缩由 HTTP 客户端(如 Apache HttpClient5)在发送时处理。

`FeignAcceptGzipEncodingInterceptor` 更简单:

```java
@Override
public void apply(RequestTemplate template) {
    addHeader(template, HttpEncoding.ACCEPT_ENCODING_HEADER,
              HttpEncoding.GZIP_ENCODING, HttpEncoding.DEFLATE_ENCODING);
}
```

仅添加 `Accept-Encoding: gzip, deflate` 头。

## 六、生产注意

- **属性路径**: 使用 `spring.cloud.openfeign.compression.*`,不是 `feign.compression.*`。后者不触发自动配置
- **请求压缩的实际效果取决于 HTTP 客户端**: 当前 Feign 拦截器仅设头。Apache HttpClient5 可能自动压缩,HttpURLConnection 不会。如需确保压缩,可自定义 `Encoder` 或使用 `feign.gzip.GzipEncoder` 包装
- **服务端响应压缩**: `spring.cloud.openfeign.compression.response.enabled` 只负责让客户端声明接受压缩响应;服务端必须另外配置 `server.compression.enabled=true` 才能真正压缩响应
- **mime-types 匹配**: 默认只匹配 `text/xml,application/xml,application/json`。如果 Feign client 发 `text/plain`,需要显式添加
- **min-request-size**: 默认 2048 字节。太小则小请求也加头(增加 CPU),太大则大请求未压缩(浪费带宽)。推荐 1KB-4KB
- **日志**: 开启 `logging.level.org.springframework.cloud.openfeign: DEBUG` 可看到压缩拦截器执行日志
