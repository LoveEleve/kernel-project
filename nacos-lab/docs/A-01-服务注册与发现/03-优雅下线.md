# 优雅下线与手动摘除

## 问题

生产环境重启微服务，直接 kill 会导致什么？

→ 调用方路由到已摘除的实例 → 连接超时 → 大量重试 → 级联故障。

## 正确的下线流程

```
应用 → deregister() → Nacos Server 通知所有订阅者 → 等待流量排干 → shutdown
```

时间线：
- T+0s：调 deregister → Nacos Server 标记实例 offline
- T+0-2s：gRPC push 通知已订阅的客户端
- T+2-5s：客户端刷新本地缓存，移除该实例
- T+5-10s：仍在路上的请求处理完毕
- T+10s：安全 shutdown

## 操作步骤

```
# 1. 确认已注册
curl http://localhost:28001/discovery/status
# autoRegistrationRunning: true

# 2. 手动摘除
curl -X POST http://localhost:28001/discovery/deregister

# 3. 等 10s，确认状态
curl http://localhost:28001/discovery/status
# autoRegistrationRunning: false, markedOffline: true

# 4. 去 Nacos 控制台 → 确认实例消失

# 5. 重新上线
curl -X POST http://localhost:28001/discovery/reregister

# 6. 确认恢复
curl http://localhost:28001/discovery/status
# autoRegistrationRunning: true, markedOffline: false
```

## @PreDestroy 钩子

启动类已有 `@PreDestroy gracefulShutdown()`：
```java
@PreDestroy
public void gracefulShutdown() {
    if (autoServiceRegistration != null && autoServiceRegistration.isRunning()) {
        autoServiceRegistration.stop(); // dereigster
    }
    Thread.sleep(5000); // 给 Nacos 通知传播留时间
}
```

验证：`kill <PID>`（SIGTERM，不是 kill -9）→ 观察日志输出 "优雅下线开始/完成"。

## 生产注意

- **kill -9 不会触发 @PreDestroy**：SIGKILL 直接终止 JVM，绕过所有钩子。必须用 SIGTERM（kill）或 docker stop
- **K8s 配置**：
  ```yaml
  lifecycle:
    preStop:
      exec:
        command:
          - /bin/sh
          - -c
          - curl -X POST http://localhost:28001/discovery/deregister && sleep 10
  terminationGracePeriodSeconds: 30
  ```
- **等待时间**：deregister → gRPC push → 客户端更新缓存，至少 5-10s。大型集群可能需要 15-30s
