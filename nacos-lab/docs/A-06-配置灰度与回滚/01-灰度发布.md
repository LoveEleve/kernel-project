# 灰度发布

## 一、灰度发布的本质

不是"把新配置发给所有实例"——是"先把新配置发给一小部分实例，确认安全后全量发布"。

Nacos 2.x 的 beta 配置就是为此设计的：创建一个"beta 版本的配置"，只有指定灰度 IP 列表内的客户端能拿到这个版本的配置。所有不在灰度列表里的客户端仍拿到正式配置。

## 二、Nacos 的内部实现

beta 配置在 Nacos Server 端是通过 `ConfigInfoBetaWrapper` 实现的——它是正式配置的一个"beta 副本"。当客户端查询配置时，Nacos 检查客户端 IP 是否在灰度列表中：

```
客户端请求 → ConfigServletInner.doGetConfig()
  ↓ 检查是否有 beta 配置
  ├── 有 beta + 客户端 IP 在 betaIps 中 → 返回 beta 内容
  └── 其他情况 → 返回正式配置内容
```

## 三、操作步骤

```
# 1. 发布 beta（仅本机可见）
curl -X POST "http://21.130.247.89:18848/nacos/v1/cs/configs" \
  -d "dataId=nacos-lab.yaml" \
  -d "group=DEFAULT_GROUP" \
  -d "tenant=sca-lab-dev" \
  -d "content=demo.message: gray-test-only" \
  -d "betaIps=21.214.97.212"

# 2. 验证：本机拿到 beta 值，其他机器拿到正式值
#    本机: curl http://localhost:28001/config/current → "gray-test-only"
#    其他: curl http://other-machine:28001/config/current → 正式值

# 3. 正式发布 → beta 被清除
#    在 Nacos 控制台直接发布 → beta 配置被自动移除
```

## 四、灰度验证窗口

发布 beta 后**至少等 1-2 分钟**再全量发布。期间检查：
- 灰度实例的日志：有没有因为新配置导致的 ERROR/WARN
- 灰度实例的监控：响应时间、错误率是否正常
- 如果有任何异常 → 立即停止 beta → 回滚

## 五、生产注意

- beta 按 IP 过滤，不能按 label/header/zone 过滤
- 已建立 gRPC 长连接的客户端可能 30s 后才拿到 beta 配置
- beta 和正式配置是独立的两个版本——取消 beta 后客户端立刻回到原正式配置
