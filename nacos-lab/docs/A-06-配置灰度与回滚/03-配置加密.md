# 配置加密

## 问题

数据库密码、Redis 密码、第三方 API Key 不能明文存在配置文件里——任何人访问 Nacos 控制台都能看到。

## 三种方案

| 方案 | 加密位置 | 密钥管理 | 推荐场景 |
|---|---|---|---|
| **Jasypt** | 应用层（解密在应用本地） | 环境变量注入 master key | 中小项目，配置项 < 50 |
| **Nacos 加密插件** | Nacos Server 端 | Nacos 内部存储密钥 | 中等项目，需要传输加密 |
| **HashiCorp Vault** | 外部密钥管理 | Vault 统一管理 + 动态密钥 | 大项目，合规要求，审计 |

## 生���推荐：Jasypt

```yaml
# application.yml — 密文以 ENC() 包裹
spring:
  datasource:
    password: ENC(a3B94f2Vj7K8xZ1yQ5wE6rT9uI0oP3sA)

# 密钥注入（不要在配置文件里写！！！！）
# 方式1：环境变量
#   export JASYPT_ENCRYPTOR_PASSWORD=your-master-key
# 方式2：JVM 参数
#   -Djasypt.encryptor.password=your-master-key
# 方式3：K8s Secret
#   env:
#     - name: JASYPT_ENCRYPTOR_PASSWORD
#       valueFrom:
#         secretKeyRef:
#           name: jasypt-secret
#           key: password
```

### 为什么 Jasypt 主流？

- **简单**：加一个 dependency、一个环境变量就行
- **应用层解密**：Nacos 里存的是密文。即使 Nacos 被攻破，没有 master key 也解不开
- **与配置中心无关**：不管是 Nacos / Consul / Apollo / ConfigMap，都能用

## 概念演示

```
# BASE64 编码（仅供概念演示，不是加密方法！）
curl "http://localhost:28001/config/encrypt/demo?raw=MySecretPassword"
```

返回：
```json
{
  "raw": "MySecretPassword",
  "encoded": "TXlTZWNyZXRQYXNzd29yZA==",
  "decoded": "MySecretPassword",
  "production_note": "生产环境用 Jasypt，不是 BASE64。ENC(...) 包裹 + 环境变量注入 key。"
}
```

### 为什么 BASE64 不等于加密？

BASE64 是**编��**，目的是把二进制转成可打印字符。任何人都可以 decode。
加密（AES/RSA）需要密钥，没有密钥解不开。

## 生产注意

- **master key 绝不能放配置文件里**：否则和明文一样不安全
- **不同环境的 key 不同**：dev 和 prod 用不同的 master key
- **key 轮换流程**：Jasypt 支持多 key 解密（`jasypt.encryptor.bean`），可用于 key 切换
- **Nacos 加密插件 vs Jasypt**：Nacos 插件是传输加密（Server ↔ Client），Jasypt 是存储加密（配置内容）——两者可以同时用
