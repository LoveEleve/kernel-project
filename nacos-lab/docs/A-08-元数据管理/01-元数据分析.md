# 元数据管理 — Nacos Instance Metadata 的生产用途

## 一、什么是 metadata

Nacos 的每个服务实例都有一个 `Map<String, String>` 类型的 metadata。它可以携带任意键值对——不是 Nacos 内部使用的，而是**给你放的**。

```java
// Nacos SDK 注册时
Instance instance = new Instance();
instance.setIp("21.214.97.212");
instance.setPort(28001);
Map<String, String> metadata = new HashMap<>();
metadata.put("version", "v2.3.1");
metadata.put("zone", "beijing");
metadata.put("weight", "3");
instance.setMetadata(metadata);
```

Spring Cloud 中，这些 metadata 通过 `NacosServiceDiscovery.hostToServiceInstance()` 流入 `ServiceInstance.getMetadata()`。

## 二、生产用途全景

| 用途 | metadata key | 消费方 | 说明 |
|---|---|---|---|
| **负载均衡权重** | `nacos.weight` | Spring Cloud LoadBalancer / NacosLoadBalancer | Nacos 原生支持，自动从 `Instance.weight` 转换 |
| **集群/Zone 亲和** | `nacos.cluster` | NacosLoadBalancer | 优先路由同 Cluster 的实例 |
| **金丝雀标识** | `version` | 自定义 LoadBalancer (B3) | 区分 canary/stable 实例 |
| **Prometheus SD** | `prometheus.port`, `prometheus.path` | Prometheus `nacos_sd_configs` | Nacos 作为 Prometheus 的服务发现源 |
| **K8s 运行信息** | `podName`, `namespace`, `nodeName` | 运维平台 | K8s Downward API 注入 |
| **JVM/应用信息** | `javaVersion`, `startupTime`, `commitHash` | 运维平台 (B1) | 实例级别的版本追溯 |
| **功能开关** | `feature.xxx` | 应用内代码 | 实例级别的功能控制 |
| **健康/启停** | `nacos.healthy`, `nacos.ephemeral` | Nacos Server | Nacos 原生支持 |

## 三、metadata 的流转

```
Nacos Instance.metadata (Map<String, String>)
    ↓ NacosServiceDiscovery.hostToServiceInstance()
    ↓ metadata.put("nacos.weight", instance.getWeight() + "")
    ↓ metadata.put("nacos.cluster", instance.getClusterName() + "")
    ↓ metadata.putAll(instance.getMetadata())  ← 用户自定义的 key 在这里合并
ServiceInstance.metadata (Map<String, String>)
    ↓ ServiceInstanceListSupplier 装饰器链
MetadataBasedLoadBalancer.choose() → 从 metadata 读取 version/zone/weight
```

**关键转换**：Nacos 的 `Instance.weight` 是 `double`，通过 `toString()` 变成 `String "3.0"` 存入 metadata。消费方（如 NacosBalancer）再 `Double.parseDouble()` 解析回来——**这个 String↔double 转换是精度损失的来源**。

## 四、Spring Cloud 内置的 Nacos metadata

Nacos SDK 和 Spring Cloud Alibaba 自动注入了以下 key：

| Key | 来源 | 值示例 |
|---|---|---|
| `nacos.weight` | `nacosDiscoveryProperties.getWeight()` | `"1.0"` |
| `nacos.healthy` | `nacosDiscoveryProperties.isInstanceEnabled()` | `"true"` |
| `nacos.cluster` | `nacosDiscoveryProperties.getClusterName()` | `"DEFAULT"` |
| `nacos.ephemeral` | `nacosDiscoveryProperties.isEphemeral()` | `"true"` |
| `nacos.instanceId` | Nacos 自动生成 | `"21.214.97.212#28001##..."` |
| `preserved.register.source` | Spring Cloud Alibaba | `"SPRING_CLOUD"` |

## 五、自定义 metadata 的注入方式

**方式 1：NacosRegistrationCustomizer（官方扩展点）**
```java
@Component
public class MyMetadataCustomizer implements NacosRegistrationCustomizer {
    @Override
    public void customize(NacosRegistration registration) {
        registration.getMetadata().put("version", "v2.0");
    }
}
```

**方式 2：自实现 ServiceRegistry（B1）**
```java
@Override
public void register(Registration registration) {
    Map<String, String> metadata = new HashMap<>(registration.getMetadata());
    metadata.put("startupTime", Instant.now().toString());
    metadata.put("javaVersion", System.getProperty("java.version"));
    instance.setMetadata(metadata);
    namingService.registerInstance(serviceId, group, instance);
}
```

**区别**：Customizer 在 Bean 初始化时设置 metadata，B1 在注册时设置——B1 能拿到运行时的真实信息（如 startupTime），Customizer 拿不到。

## 六、生产最佳实践

**命名规范**：
- Nacos 原生 key 用 `nacos.*` 前缀
- 业务 metadata 用 `business.*` 前缀（如 `business.version`, `business.zone`）
- K8s 信息用 `k8s.*` 前缀

**不要做的**：
- 不要把密码/密钥放入 metadata（明文传输，Nacos API 可读）
- 不要把频繁变化的值（如 ThreadPool.activeCount）放入——每次变化都要更新 Nacos
- metadata 大小限制 ≈ 每实例 ≤ 4KB（取决于 gRPC frame 大小）
