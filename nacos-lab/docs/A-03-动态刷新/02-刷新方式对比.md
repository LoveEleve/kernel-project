# @RefreshScope vs @ConfigurationProperties 对比

## 一、本质区别

| | @Value + @RefreshScope | @ConfigurationProperties |
|---|---|---|
| 刷新原理 | Bean 代理重建（proxy 不变，target new） | Environment 更新 → 属性 rebind |
| Bean 生命周期 | 销毁旧 target → 创建新 target | Bean 不销毁，属性更新 |
| 性能 | 重建整个 Bean（依赖注入重做） | 仅更新 Environment 中的 PropertySource |
| 适用 | <5 个独立配置项 | >=5 个，结构化配置类 |

## 二、为什么 @ConfigurationProperties 更优

```
@RefreshScope 刷新时：
  destroyOldBean() → 调用 @PreDestroy → 清理旧资源
  createNewBean()  → 构造函数 + @PostConstruct + 依赖注入
  → 如果 Bean 持有 HikariCP 连接池 → 全部连接断开重建

@ConfigurationProperties 刷新时：
  refreshEnvironment() 更新 PropertySource
  ↓
  下次 getter 调用 → 从已更新的 Environment 取值
  → 不触发任何 Bean 生命周期方法
```

## 三、验证

```
# 两种方式都拿到新值
curl http://localhost:28001/config/refresh-compare | python3 -m json.tool
# properties_* 来自 @ConfigurationProperties
# value_* 来自 @Value + @RefreshScope
# 修改 Nacos 配置后两者同步更新
```

## 四、生产推荐

- 5 个以上配置项 → @ConfigurationProperties（不重建 Bean）
- 需要 @PostConstruct 初始化 → @RefreshScope（重建自然触发）
- 方式功能开关 → B2 自定义 Listener（比两种都精确）
