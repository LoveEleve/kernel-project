# 03-原理二：同区域优先算法

## §0 它干了什么（例子先行）

LoadBalancer 把 8 个实例递给过滤器，同区优先怎么判（filter:66 全分支读码）：

```
① 列表<=1？            → 原样返回 :72
② 总开关/偏好开关关了？  → 原样返回 :79/:85（偏好默认关——README"建议显式开启"）
③ zone 是空/defaultZone？→ 原样返回 :92（没定位到就别谈偏好）
④ 剔除 disabled-zone 的实例
   → 剔完<=1？           → 返回【原始全量】:108（禁用区名单太狠=自废武功）
⑤ 统计：带 zone 的实例占比 < 就绪率阈值（默认 100%）？
   → 是 → 返回 targetEntities :137（多数实例没带 zone 元数据=土壤没铺好）
⑥ 同 zone 实例数 < 最小可用数（默认 5）？
   → 是 → 返回 targetEntities :148（同区就俩，全压过去=把俩打死）
⑦ 否则 → 返回同 zone 实例 :153 ✅
⑧ 一个同区都没有 → 返回 targetEntities :159（跨区也得服务）
```

- **它干了什么**：**每一次"不满足"都退化为可用列表**——偏好是优化，永远不是可用性的对手。
- **本篇回答**：三个阈值各保护什么？退化时 disabled 区为什么还剔着？

## §1 概念铺垫（What：三阈值 + 一语义）

| 词 | 默认 | 一句话 |
|---|---|---|
| **zone-ready-percentage** | 100 | 带 zone 元数据的实例占比下限——**下游没接传播（或注册没带 metadata）就整体退化**（与 04 篇注册传播呼应） |
| **same-zone-min-available** | 5 | 同区最少几个——**防"同区孤岛过载"**（少于 5 个说明这个区撑不住，别把鸡蛋都放这） |
| **disabled-zone** | 空 | 手动拉黑故障区——**即使随后退化，被拉黑的也不回来**（读码细节：退化返回 `targetEntities`=已剔除列表:137/:148，只有④太狠才回原始 `entities`:108） |
| **退化保底** | - | **"偏好不能导致无实例可用"**（README :138 原话）——每步 early return 都是兜底 |

## §2 关键推导（两问）

**① 为什么就绪率默认 100% 这么严？**
它保护的是**基础设施完整性**：如果只有 30% 实例带 zone，说明大多数实例没走注册传播（04 篇 ZoneAttachment 的依赖）——此时开偏好=用 30% 的信息做 100% 的路由决策，**信息不全就不决策**。宁可跨区，不赌。

**② 同区 2 个实例，为什么不让选？**
`same-zone-min-available=5`：同区实例太少=该区容量存疑，**全压同区=故障放大器**（一个实例倒下就是 -50% 容量）。这与 02 篇"fast-fail 默认关"同哲学——**默认永远选可用性**。

**③ 与负载均衡链的关系（回链 loadbalancer 系列）**：
本过滤器是 LB Supplier 里的**候选集过滤器**：它不是独立的、可排序的 filter，而是被 `ZonePreferenceServiceInstanceListSupplier` 包在 `withCaching()` 之后——先缩列表，**原有负载均衡策略再在幸存者里挑**（README :89 原话"过滤出同区域实例，再交给原有负载均衡策略"）。过滤器不选实例，只**改候选集**。

## §3 掌握卡（2 条）

1. **十步结构**：三关（能力/偏好/zone 有效）→ 三阈值（禁用区/就绪率/同区最小数）→ 命中或退化——**每步 early return 都是保底**。
2. **disabled 语义的精读**：④太狠回原始全量 :108；⑤⑥退化回"已剔除 disabled 的列表" :137/:148——**黑名单在退化态依然有效**（README 伪码没细说，源码给了答案）。

## §4 边界（一句话翻篇）

- ZoneResolver 泛型解析（怎么从实例里取 zone）→ 按需读。
- 过滤器的插入位置由 LB Supplier 链决定（本项目固定为 caching 之后）→ 05 篇接线。
- Supplier 同名撞车：本系列 `ZonePreferenceServiceInstanceListSupplier` 与 SC 内置**同名不同包**——javadoc:30 自称其"optimized replacement"（05 篇接线讲怎么换）。
