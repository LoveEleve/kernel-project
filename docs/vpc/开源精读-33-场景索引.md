## 一、它是什么——"六视角 × 多场景"的证据矩阵

每个场景都由同一套**六视角**拍完整快照：

```
① 场景说明/操作步骤 → ② 操作日志（t_log_*.TVPC.* 原始记录）→ ③ 实例表（DB 真相：t_vm/t_rti/t_rtb_route…）
→ ④ ZK 结构（/TVPC/HOST|VM|ENI|RTABLE… 实树）→ ⑤ 母机/网关配置（route_table/neigh_table/fdb/vhost/QoS）
→ ⑥ 连通性测试 + 抓包分析 + 报文交互（Wireshark 分层 + 逐 Step 报文）
```

**同一件事的六层快照**——这正好是全课程"配置从 API 到 DPDK"各层机制（16/19/25 课）的**实物对账材料**：课里学的每一跳，这里都有一份"当时那一跳长什么样"的存证。

## 四、抽样看点（带行号，已人工核对）

**看点 1：GRE 报文的"三重身份"**（@1328 起，主动出公网抓包）：

| 层 | 字段 | 值 | 解读 |
|---|---|---|---|
| GRE 头 | **Key** | `0x004ea658` | **= 5154392 = vpcId**——34 课"GRE key=vpcId"的**报文级实证** |
| GRE 头 | **Sequence Number** | `167772162 / 167772433` | **= 内网 IP 的 32 位整数**（167772433=0x0A000111=**10.0.1.17**；文档 @1615 原文注："对应 intIp=10.0.1.17"）——**数据面小聪明：把源 IP 藏进 Seq** |
| 外层/内层 | Src/Dst | 母机IP / TGW TSVIP(9.27.88.133)；内层=公网 EIP → 8.8.8.8 | 三层叠法（mac→inner→outer）与 34 课"叠包法"逐个对上 |

**看点 2：TGW NAT 段三段抓包**（@1597-1640）——见 §五 补记。
**看点 3：ZK 值格式**（@1034）：`/TVPC/RTABLE/5154392/10.0.1.0|24 → 10.0.1.17-11.71.172.145`——**值="VM IP - 母机 IP"** 的点号对格式（4/7 课 ZK 树的实物注解）。
**看点 4：HAVIP 选主机制**（TOC @196 专节）——选举的"平台内版本"（对照 20/26 课）。

## 五、TGW 补记（给 34/35 课"挂账"回填）

从 NAT 段抓包（@1599-1640）可确证的事实：

- **TGW 是"公网出口的 GRE 中转"**：包路径 = 客户端母机 →（GRE key=vpcId）→ **TGW（9.27.88.133 TSVIP / 9.255.46.45）** → 公网 8.8.8.8；
- **NAT 发生在"网关母机"侧**：内层 Src 已是 NAT 后公网 IP（`81.71.44.54`）——即 VPCGW 的那一跳（34 课 `add_wan` 的 DNAT/SNAT 实物）；
- **回包三段**（TGW→网关母机→客户端母机）：内层 Dst 逐段还原（公网 IP → 10.0.0.2）——**NAT 的两半（SNAT 出、DNAT 回）在抓包里被逐段拍下**；
- **TGW 仍无专篇**：以上为"抓包级证据"；控制面管理（`vip_tgw` 资源如何配 TGW）**仍挂账**——但"两处半空白"已实缩为**"一处半"**（TGW 数据面路径已实证，控制面细节欠）。
