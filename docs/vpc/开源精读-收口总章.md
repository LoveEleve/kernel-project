## 一、三条链合璧图（十三课拼出的全景）

```
【底座】   etcd(3) / ZooKeeper(4)——两种"协调内核"；DPDK(12)——数据面底座
             │
【控制面写侧】
   我们：sdn_oss（Saga+Outbox）      kube-ovn(1)：CRD→NB        TF(6)：config→IF-MAP 图
             │                              │                        │
【分发与 agent】
   我们：nfv-proxy/agent-broker     OVN(5)：northd→SB→ovn-controller   TF(6)：control-node→XMPP
             │  （calico(2)：typha fan-out + felix calc graph；cilium(10)：策略编译进每 Pod 程序链）
【数据面】
   我们：vpcko(内核)+DPDK 通道      TF(7)：dp-core×四壳      DPVS(8)：DPDK-FNAT
   Katran(9)：XDP    OVS(11)：两段流表（OpenFlow→microflow）
```

## 二、一个方程：增量 + 全量兜底（九处实例）

第 5 课做了四见表，十三课读完，实例升到**九**：

| 系统 | 增量机制 | 全量/兜底 |
|---|---|---|
| calico felix(2) | calc graph delta | full resync（`int_dataplane.go:2320`） |
| etcd(3) | watch unsynced 补课 | 压缩边界 `ErrCompacted` → 客户端快照 |
| 我们（对照地图） | /BINLOG + Inspector 对账 | CKV 快照重拉 + 报告制对账 |
| OVN(5) | I-P engine change_handler | `change_handler = NULL` → run 全量重算 |
| DPVS(8) | 会话超时按状态清除（S_NONE 2s…ESTABLISHED 90s） | 超时即"无状态"，下个包重新走全流程 |
| Katran(9) | per-CPU LRU 会话 | RST/flood 不写表 → 等价全量重算 |
| cilium(10) | callsmap 换槽位（增量更新执行段） | **Regenerate：整个 endpoint 数据面描述重建** |
| OVS(11) | microflow 命中（快路径） | **upcall → OpenFlow 慢路径重新翻译** |
| overlay(13) | 直连打洞（尽力直连） | 中继兜底（DERP "last resort"） |

**结论固化**：任何"有状态 + 要正确"的转发/分发系统，答案都是"快路径增量、慢路径全量、两者周期相交"。差异只在**兜底的触发条件**（resync 周期 / 压缩水位 / 对账批次 / TTL / LRU 淘汰 / 换槽位失败 / upcall / 打洞失败）。

## 三、三世界观 + 两问：状态放哪、逻辑放哪

**配置模型的世界观**（第 1/3/4/5/6 课合璧）：

| 世界观 | 代表 | "选谁下发"的代价 |
|---|---|---|
| **图** | TF IF-MAP（GraphWalker 沿关系切子图） | 软件复杂度换选择精度 |
| **树** | ZK（我们一代 / kube-ovn 语境） | 结构约束换简单；关系靠约定 |
| **平铺 KV** | etcd | 约定纪律换灵活；关系靠前缀 |

**数据面"状态放哪"**（第 7/8/9/10/11 课合璧）：

| 放哪 | 代表 | 代价 |
|---|---|---|
| **流里**（per-flow 状态） | tf-vrouter、Katran（LRU）、DPVS（conn 表） | 内存/首包/失效管理 |
| **per-lcore / per-CPU** | DPVS（share-nothing）、Katran（array-of-maps） | 容量×核数、大流偏斜 |
| **不放**（无状态转发） | 我们 vpcko（LPM）/ Katran 的回包（DSR） | 功能范围窄；状态外移 |
| **vswitch 里也放**（CT zone） | OVS | 连 conntrack 生命周期都归用户态管 |
| **身份+CT 表**（eBPF map 族） | cilium（ctmap / ipcache） | 一致性面变宽（身份分配/回收） |

**转发/策略逻辑"放哪"**（第 9/10/11/12 课合璧——"**可编程数据面三方言**"）：

| 放哪 | 代表 | 形态 |
|---|---|---|
| 固定流水线里查更多的表 | 内核栈 / OVS datapath | 逻辑固定、数据可配 |
| **流表下沉** | rte_flow（DPDK）、OpenFlow | "匹配-动作"描述，可下到网卡 |
| **程序装载** | XDP/eBPF（Katran/cilium）+ BPF map | **逻辑本身是可装载的程序** |

## 四、一致性责任的三种答卷

| 答卷 | 代表 | 债记在哪 |
|---|---|---|
| **Saga + Outbox** | 我们 sdn_oss | 补偿链复杂度；换来"失败半途可回滚+保投递" |
| **声明式无限重试** | kube-ovn(1)、calico felix(2) | 永不放弃 = 错误可能被掩盖；需要 status/converge 可观测 |
| **无事务直接推** | TF(6)（附录 A："无 Saga/Outbox"） | 债在"推丢了怎么办"——靠 Introspect 对账兜 |

对账姿态也分两种：**报告制**（我们：只报告不修——多租户误修代价高）vs **自动修**（felix resync、OVN 重算——单租户域敢兜）。
