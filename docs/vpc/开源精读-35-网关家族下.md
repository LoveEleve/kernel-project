## 0. 术语速查

| 术语 | 含义 |
|---|---|
| **IPsec 两阶段** | IKE Phase 1（ISAKMP SA：认证+协商）+ Phase 2（IPsec SA：ESP/AH）——**ESP 包结构**=Outer IP（不加密）+ ESP Header + 加密的 Inner IP/Payload |
| **DPD** | **Dead Peer Detection**："定期探测 peer 是否存活……探测间隔 **10s**，重试 **3 次 = 30s 检测时间**" |
| **专线（DC）** | 物理专线（光纤，1G/10G/100G，<2ms）与虚拟专线（MPLS/VPLS，"**物理/虚拟对控制面透明**"）；控制面模型同是 `t_dc_gateway` |
| **BGP session** | DCGW ↔ IDC Router：宣告 VPC CIDR / 学到 IDC 路由（材料给了完整 `router bgp` 配置样例） |
| **vgwType=2** | 专线路由的下一跳类型（Peering=3 / CCN=4 之后补齐的第三块拼图） |
| **Flow Log** | 记录流量**五元组**（"不抓包内容——只记元数据"）入 CLS；DPDK 采集 → 5 分钟聚合 → 上报 |

## ① 它干了什么——"最后一公里"的两条路

前面所有课的网络边界都在云内；这一课补上**云的边界**：VPC 想和"自己机房的 192.168.0.0/16"说话——

- **便宜的走法（VPN）**：公网之上打 IPsec 隧道——**IKE 两阶段协商密钥**、ESP 加密包、**DPD 每 10 秒探测对方死没死**（3 次失败=30 秒判定），"VPN 便宜但不稳定"；
- **贵但稳的走法（专线）**：运营商拉光纤（**1G/10G/100G 独占，延迟 <2ms**）——**物理/虚拟专线对控制面透明**；控制面建 `t_dc_gateway` + `t_dc_channel`，**BGP session 与 IDC 路由器互学习路由**；
- 两条路的共同终点：**把 IDC 网段写进 VPC 路由表**（`nextHop=dc-gw/vpngw, vgwType=2`——"下一跳是通往 IDC 的那扇门"）。

**一句话**：**VPN 是"公网上的加密隧道"，专线是"物理上的私有光纤"——控制面把它们统一成"一条带 BGP 的边界路由"**。

## ② 链路走查（材料行号）

### 跳 1：VPNGW——公网上的加密隧道（hybrid-cloud §一）

**IPsec 协议栈**（§1.1）：**IKE Phase 1**（ISAKMP SA：认证 PSK/证书 + 协商 DH Group/AES256/SHA256——"用于保护后续的 IKE 消息"）→ **IKE Phase 2**（IPsec SA："ESP 或 AH；AES256-GCM（推荐）"——"加密数据包"）→ **ESP 包结构**（`Outer IP Header（公网 IP，不加密）` + `ESP Header（SPI+Sequence）` + `ESP Payload（Inner IP+TCPUDP，加密）` + `ESP Trailer + Auth Data`）——**"外层找路、内层保密"**，与 GRE（第 34 课：换标签）是"同一叠包法、不同承诺"。

**控制面**（§1.2）：`CreateVpnGw {vpcId, bandwidth}` + `CreateVpnConnection {vpnGwId, peerIp, preSharedKey, ikeVersion, ipsecAlgo}` → `INSERT t_vpn_gateway (vpcId, gwIp, state=CREATING)`——"钥匙与算法都是配置"（对照第 32 课安全六层：这里的 PSK 就是"服务间静态 token"的边界版）。

**DPD**（§一尾）："定期探测 peer 是否存活 → peer 无响应 → 重新建立 IKE SA"——**10s × 3 = 30s**——与第 23 课 keepalive 30-60s、第 34 课 HARP 多路径探测同族：**"边界设备必须自带'对方死没死'的判定器"**。

### 跳 2：专线 DCGW——物理世界的私有通道（hybrid-cloud §二）

**链路分层**（§2.1）：**物理专线**（"运营商在数据中心和腾讯云之间拉光纤——独占带宽（1G/10G/100G）……延迟 < 2ms（同城）"）与**虚拟专线**（"基于 MPLS/VPLS 的虚拟电路——共享物理链路但逻辑隔离……< 5ms"）——"**物理/虚拟对控制面透明**"（**控制面抽象又一次抹平物理差异**——第 18 课"generic"的手艺）。

**控制面**（§2.2）：`INSERT t_dc_gateway (vpcId, state=CREATING)` + `INSERT t_dc_channel (dcGwId, vlanId, peerIp, bandwidth)`——**注意分工**："运营商：配置物理线路 + VLAN——**不是控制面的操作**"（**云管逻辑链路、运营商管物理链路**——责任的边界条款）；**BGP session**（材料给配置样例）：

```
router bgp 65001
  neighbor 203.0.113.1 remote-as 65002
  network 10.0.0.0/16         ← 宣告 VPC CIDR
→ IDC Router 学到 VPC 路由；DCGW 学到 IDC 路由（192.168.0.0/16）
路由: t_rtb_route INSERT (dest="192.168.0.0/16", nextHop=dc-gw, vgwType=2)
```

**VPN vs 专线**（§2.3 材料原表）：

| | VPN | 专线 |
|---|---|---|
| 链路 | 公网 | 运营商专线 |
| 延迟 | 公网延迟 + 加密 | **< 2-5ms** |
| 带宽 | 受公网限制 | **1G/10G/100G 独占** |
| 加密 | IPsec AES256 | **不加密（物理隔离）** |
| 可靠性 | **DPD 检测 + 重新协商** | **SLA 99.95%** |
| 成本/月 | ¥数百-数千 | ¥数千-数万 |
| 适用 | 临时、备份、低成本 | **生产、大流量、低延迟** |

**读法**：这张表是"**安全/成本/可靠性三角**"的教科书——**专线不用加密，因为物理隔离本身就是加密**；VPN 用加密换成本。**边界的选型从来不是技术选型，是"你愿意为确定性付多少钱"。**

### 跳 3：混合云路由——BGP 自动学习（hybrid-cloud §三）

**手动 vs 自动**（§3.1）：

```
手动路由的问题: 每次 IDC 增加子网 → 手动更新 VPC 路由表——【不可扩展】
BGP 自动（双向）:
  IDC → DCGW: IDC 宣告 192.168.0.0/16 等 → DCGW 自动加 t_rtb_route + Fusion 展开
  VPC → IDC: VPC 子网创建 → DCGW 宣告 10.0.1.0/24 给 IDC Router → 对端自动更新路由
```

**BGP 在控制面里的"流水线"**（§3.2）：`BGP 学习 → dc_gw_bgp_route 表 → 映射 t_rtb_route (vgwType=2) → Fusion 展开 → t_rtable → Broker → Agent`；**撤路同权**："BGP Withdraw → DCGW 删除对应 t_rtb_route → Fusion 删除展开的 t_rtable 条目"——**"撤路也是事件，删除和新增走同一条流水线"**（对照第 22 课"DELETE 不是 Put(nil)"、第 32 课"DELETE 也是一条 binlog"——**删除语义三连**）。

**一个大对照**：第 30 课论证过"**BGP 不适合 VPC**"（无租户概念/1000 万路由/convergence 分钟级）；这里 DCGW-IDC 边界却**恰用 BGP**——为什么？因为**边界形状全变了**：规模是"一对 IDC 路由器"（不是 10 万台母机）、对方本来就是 BGP 世界、路由数量小且跨自治域。**"BGP 的一切缺点在 IDC 边界都不成立"**——约束决定架构，第 N 次。

### 跳 4：高级特性速览——"控制面即产品"（12-advanced / 13-dns-quota）

这批"高级特性"的共同骨架：**新配置类型 + 新数据面动作 + 性能预算**——全是第 32 课"新增配置类型 9 步流程"的实例：

- **Flow Log**（§一）：记录流量**五元组**（"不抓包内容——只记元数据"）→ 控制面 `INSERT t_flow_log (vpcId, resourceType, resourceId, logsetId, topicId)` → 全链下发 → Agent 从 DPDK 采集"包数、字节数 → 定期聚合（如 5 分钟）→ protobuf → CLS"；**SQL 可直接查**（"`SELECT src_ip, dst_ip, SUM(bytes) ... WHERE dst_port=80 GROUP BY ...`"）；**性能预算**："对转发延迟影响 **< 1%**、CPU ~**2-5%**"；
- **Traffic Mirror**（§二）：`CreateTrafficMirror {sourceEniId, targetIp, filter{...}}` → `t_traffic_mirror + filter` → Agent `add_mirror(...)`——DPDK 流水线插入 **`match(filter) → clone_to(targetIp) + forward(original)`**（"原始包正常转发、镜像包 clone 后 GRE 到监控设备"）；性能"每包 clone+GRE **~1-2% CPU**"；**三条约束自曝**（"目标 ENI 必须在同一 VPC／目标 ENI 不能绑定安全组／源和目标不能是同一 VPC 的不同子网（**同子网 OK**）"）；
- **DHCP IP**（§三全展开）：让用户**指定内网 IP**（"必须用 10.0.1.100"）——`CreateVM {subnetId, privateIp}`；**校验三步**：① 在子网 CIDR 内？② **不是保留 IP（网关 .1、网络 .0、广播 .255）**？③ `t_ip` 中该 IP `flag=0`（可用）？→ 分配 `UPDATE t_ip SET flag=1`；**三失败场景**齐备（"IP 不可用／保留 IP 不能分配／IP 不在子网范围内"）；**三使用场景**："网络设备（VPN/防火墙）需要固定 IP／服务器迁移保持 IP／遗留系统硬编码 IP 上云"。**VPC 内置 DNS**（13 篇 §1）：**`169.254.0.2`（VPC 内置，保留 IP）**——与 34 课 RNET"169.254.x.x 系统 Service"呼应 + 自定义 DNS（`INSERT t_vpc_dns`）。**13 篇其余两节（多 AZ 容灾 §二 / 配额与限制 §三，含"配额 vs 容量"）本课取头部**——与 31/32 课容量主题同宗，留待需要时深挖。

**读法**："高级特性"不高级——它们是**控制面产品的边界展台**：可观测（Flow Log）、诊断（Mirror）、服务化（DNS）——**每一种都是"一条配置类型 + 一个 DPDK 动作 + 一份性能预算"**。控制面的产品力=配置类型的丰富度（第 18 课"105 种"的又一次现身）。

## ③ 设计推导（问题树）

**Q1："云内不走 BGP、云外才走 BGP"——这个翻转说明什么？**
第 30 课的三条否决理由（无租户概念／千万路由／convergence 分钟级）**全部以"云内规模"为前提**；到了 IDC 边界：对端是**单个 BGP 路由器**、路由是**跨自治域的少量网段**、对方**本就活在 BGP 世界里**——同一个协议从"绝不能用的副作用"变成"必须用的标准件"。**选型跟着约束走，不跟着协议的名声走**。

**Q2：为什么"BGP Withdraw 的流水线"值得单独记？**
因为它证明**删除是"一等公民"**：撤路→`t_rtb_route` 删→展开条目删——与新增走**同一条链**。对照三连（22 课 `Put(nil)` 事故、32 课"DELETE 也是 binlog"、本课 Withdraw）——**删除语义的完整度，是判断一个控制面成熟度的试金石**。

**Q3：专线"不加密"与安全六层怎么互洽？**
"加密"这件事**由链路的归属者负责**：专线是"物理隔离"（安全发生在拉光纤那一刻），所以云侧不需要 IPsec；VPN 走公网——安全责任回到 IPsec 参数（PSK/AES256/DH Group——都是**配置**）。**"安全责任落在谁家"取决于链路是谁的**——这也是 30 课"约束决定架构"的安全版。

**Q4：Flow Log 的"<1%"与 Mirror 的"~1-2%"为什么必须写出来？**
因为**数据面动作都有物理代价**：每包 clone/记录=多一次内存操作+封装——不写预算的"高级特性"就是耍流氓。对照第 12 课 DPDK 底座、25 课 rtable 基准——**"性能预算在每个动作处报警"**是这套系统的默认纪律。

**Q5：从"网关家族"回看"闭环问题"（你最初的质疑）——现在闭环了吗？**
**云内四边界已闭环**：公网（VPCGW/NATGW/EIP）／跨 VPC（PVGW/PL GW/CCN GW）／IDC（VPN/DCGW/BGP）／服务消费（PrivateLink）——每种都有**控制面流程+数据面动作+HA/约束**。**仍未闭环**：① 各 GW 的**数据面内部容量/老化**（NAT 会话表、CCN 隧道管理——材料到"GRE encap"为止）；② **TGW 专篇**（`vip_tgw` 仍是只见名词）；③ 13 篇的**多 AZ 容灾/配额**两节（头部已摘，深挖挂账）。**诚实刻度：从"三处空白"缩到"两处半"。**

## ④ 对照卡：网关家族全家族总表（34+35 收官）

| 边界 | 网关 | 语义 | 数据面 | HA / 约束 |
|---|---|---|---|---|
| VPC ↔ 公网 | **VPCGW** | NAT 换身份（SNAT+DNAT） | `add_wan` + 默认路由 | **HARP**（65357/65358）；切换窗口=同步+收敛 |
| VPC ↔ VPC | **PVGW** | **GRE 换装**（key A→B） | 解→查→再封 | 多实例 LB；VIP 只是控制面概念 |
| 服务消费 | **PrivateLink / PL GW** | 单向暴露 VIP:Port（**跨 Region ✅**） | **PL GW GRE 中转** | `acceptanceRequired` 审批 |
| 多 VPC/多 IDC | **CCN GW** | 全网状自动化 | 查全网状→跨 Region GRE | 1 次配置；自动最优路径 |
| VPC ↔ IDC（隧道） | **VPNGW** | IPsec（IKE 两阶段+ESP） | ESP 加解密封装 | **DPD 10s×3=30s**；PSK/算法皆配置 |
| VPC ↔ IDC（专线） | **DCGW** | 物理/虚拟透明 + **BGP** | 专线 → BGP 学习/宣告（vgwType=2） | **SLA 99.95%**；运营商管物理层 |

**一句话收官**：**母机是"院内交通"，网关是"海关与领事馆"**——出公网=海关（换身份）；跨 VPC=领事馆（换标签不换人）；去 IDC=大使馆（BGP 外交条款）；而 **EIP/CLB/Flow Log 们是"护照业务与观景台"**——控制面把每条边界都做成了**可配置、可计费、可观测的产品**。
