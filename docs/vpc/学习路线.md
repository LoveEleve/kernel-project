## 一、使用说明（怎么才算"学完一块"）

1. **例子先行**：每块先拿一个具体例子讲清"它干了什么"，再展开。
2. **闭卷验收**（三档）：
   - 对象层 = 能**画关系图**（不看资料）；
   - 场景层 = 能讲"用户动作 → 配置组合 → 数据面路径"**三件套**；
   - 机制层 = 能讲**每一跳的失败模式 + 恢复路径 + 为什么放在这里**。
3. **每块产出物**：闭卷画一遍 → 存档到本目录（文件名：`A1-对象关系图.md` 等）。
4. **数字带口径**：不确定的数字标"待源码核实"，不硬编。

## 二、总览

```
线 A · 业务与对象模型（学一次，三代共用——对象模型在代际间基本不变）
  A0 概念与坐标系 → A1 对象关系图 → A2 数据模型三原则 → A3 八大业务域 → A4 场景族端到端 → A5 生命周期与级联

线 B · 架构与机制（一代、二代各走一遍；三代复用同一套问题账本）
  B1 一代主线 → B2 ★一代问题账本 → B3 二代主线（逐条答案）→ B4 按层深挖 → B5 横切收口

耦合检查点（贯穿）：每学完 A4 一个场景 → 回线 B 追问
  "这个场景的配置走了哪些配置类型？放大成几条转发？失败在哪一跳、怎么恢复？"
```

**建议顺序**：**A0** → A1 → A2 → B1 → B2 → A3 → A4 → B3 → B4 → A5 穿插 → B5 → 段位切换（三代）。

## 三、线 A · 业务与对象模型

### ☐ A0 概念与坐标系（薄，但必须有——回答"VPC 是啥 / SDN 是啥"）

- **内容**：① 云计算 → 云网络 → VPC 的来龙去脉（为什么需要"虚拟私有网络"）；② **SDN 一句话**：控制与转发分离（控制面算配置 / 数据面执行转发）；③ **核心术语速查**：VPC / 子网 / ENI / 子机 / 母机 / GRE / EIP / 网关族 / vhost / ECMP；④ 三个视角的关系（产品 / 业务 / 数据流——为什么选数据流当主轴）。
- **素材**：`test-good/00-background/{01-vpc-basics, 02-distributed-infrastructure, core-objects, vpc-core, add_vpc}.md`；`docs/精要卡-49/50/51`；`docs/面试主线图-创建VM.md`。
- **产出**：一张"坐标系图"（VPC 是什么 + 术语表 + 控制面/数据面划界）。
- **自测**：用一句话向非同行解释：VPC 是什么、控制面/数据面怎么分工、母机是干嘛的。

### ☐ A1 对象关系图（核心对象 + 两个模型怎么分家）

- **内容**：VPC → 子网 → IP → ENI → VM（资源侧）；rtb/rtb_route/rule ↔ rtable（策略侧 vs 转发侧）；ACL（子网级/无状态）vs 安全组（实例级/有状态）；网关族（VPCGW/PVGW/NATGW/TGW/VPNGW/CCN/DCGW）。
- **素材**：`test-good/00-background/{core-objects, vpc-core, 03-vpc-subnet-ip, 04-vm-eni}.md`；`docs/精要卡-49/51/52`；`docs-by-topic/03` §对象模型。
- **产出**：手绘对象关系图（含"一条策略 × N 台 VM = N 条转发"的分离点）。
- **自测**：① 一条路由策略最终怎么变成转发条目？② ENI/IP/VM 三者是什么关系？③ 安全组和 ACL 挂在哪一级？

### ☐ A2 数据模型三原则

- **内容**：三表分离（t_rtb → t_rtb_route → t_rule，解决策略复用）；策略与转发分离（1 条策略 ↔ N 条 VM 级转发，展开是独立阶段）；无外键是刻意（高频变更下校验开销 > 一致性收益）。
- **素材**：`test-good/07-advanced/first-principles.md`；`vpc-gen2/14-business-scenarios.md` §数据模型三关键；`VPC控制面.md` 表设计段。
- **产出**：三原则卡片——每条写"它解决什么硬约束、代价是什么"。
- **自测**：① 为什么无外键？② 为什么策略和转发要分离（直接存转发表不行吗）？

### ☐ A3 八大业务域 × 代表配置类型

- **内容**：路由（12）/ 网络对象（15）/ ACL（7）/ 高可用（3）/ 流量镜像（6）/ 服务网关（12）/ 可观测（2）/ 跨 AZ（3）——每域挑 2-3 个类型，讲"写到哪张表、展开成什么转发"。
- **素材**：`test-good/00-background` 全 23 篇；`vpc/interview/.../题库-业务领域`（48 题）；**精要卡-49~60**（VPC/IP/基础设施/VM与ENI/路由/策略/公网/跨VPC/混合云/LB高可用IPv6/VPCGW-PVGW/高级特性/DNS多AZ）；`reference/配置类型速查表.md`（55+ 类型）；`docs/业务配置类型-补全清单.md`（105/74/54 口径）；`vpc5.0-business-capabilities.md`。
- **产出**：8 域 × 代表类型卡片。
- **自测**：① EIP 的两种形态？② NATGW 的 4 个 IP 各是什么？③ HAVIP 切换流程与窗口？

### ☐ A4 场景族端到端（以《VPC通信场景技术文档》为主干）

- **主干素材（首选）**：`test-good/VPC通信场景技术文档.md`（8401 行 / 6 章 / **~50 个独立场景** / 106 节）——每个场景都是"**四层穿透**"完整版：场景说明 → 操作日志(t_log) → 实例表 → **ZK 结构** → **母机配置(/proc/net/tvpc)** → 连通性验证 → **抓包分析** → 报文交互。索引版：`docs/精要卡-63-VPC通信场景操作手册.md`；GRE 复用速查：`精要卡-61-20场景与GRE复用`；补充：`docs/面试主线图-创建VM.md`（API→DB→分发→数据面主线）。
- **场景清单（按章）**：基础互通（跨子网）；公网出访（主动出公网/子机网关/按需网关/辅助 IP）；内网高级（HAVIP/CRS 内网+公网/内网 LB×4/公共服务/公网 LB）；跨 VPC 与独立（PrivateLink/EIP+内网 LB/容器网络/PEER 同地域+跨地域/JNSGW/子网广播）；网关场景（广播×2/组播/NATGW/VPN/VPC0 实虚互访/基础网络系列/CLASSICLINK/自研 VPC/LBNAT/专线网关）；高级（专线转发/就近专线/IPv6×6/CCN/私网 NAT/NATGW 主动外访）。
- **学习法**：每个场景按"三件套"验收（用户动作 → 配置组合 → 数据面路径），并用"四层穿透"自检——闭卷说出：写了哪张表 → ZK 哪些节点 → 母机哪些表 → 抓包什么形态。
- **辅助素材**：`test-good/00-background/14-business-scenarios.md`；`题库-业务领域` Q13-22；`vpc-gen2/14 章`。
- **自测**：PrivateLink 的六段路径 + 三层 NAT？GRE 字段复用的四个场景？

### ☐ A5 生命周期与级联

- **内容**：创建依赖链（VPC → 子网 → IP → VM → ENI → 路由）；删除依赖图与级联清理；级联订阅/Watch 触发链（一代版：一台母机上线时的 20+ 种级联 Watch）。
- **素材**：`docs-by-topic/03` §依赖链；`test-good/05-cross-cutting/02-control-plane/lifecycle.md`；`VPC控制面.md` §级联 Watch 触发链。
- **产出**：创建顺序图 + 删除依赖图 + 级联触发链。
- **自测**：① VPC 被删但子网还在会怎样（对账视角）？② 一台母机的 VM 迁移会牵动哪些配置？
