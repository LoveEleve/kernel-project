# VPC 讲解方式（Design-Derivation 驱动）

> 依据：本地 skill `design-derivation`（`.opencode/skills/design-derivation/SKILL.md`）——用户规范："**所有未来框架/系统讲解默认 = 问题驱动核心原理提取**，退役逐行源码 review"。
> 本文件回答：每节课**怎么讲、怎么验收、产出什么**。与 `学习路线.md` 配套使用（路线管"学什么"，本文管"怎么讲"）。

---

## 一、每课 = 一棵"问题树"的一枝（skill 的核心结构）

```
第 0 步 · 立 baseline + 提问：先把现状方案拆成**假设清单**（逐条标楼层），再提一个具体问题
   —— 没有 baseline 的"为什么不 X"是**伪推导**（skill 红线）；三把尺子：能删吗(Descartes) / 谁要求的(Musk) / 拆开重组还成立吗(Boyd)
   例：baseline = "VPC 靠 ZK Watch 通知"；问题 = "为什么会有 binlog？没有它会死在哪？"

第 1 步 · 五段式链条（skill 规定动作，缺一不可）：
   Question   → 问题
   Naive      → 最直觉的答案
   BUT        → 直觉答案失效在哪（要能画出具体失效场景）
   Therefore  → 被迫的设计（唯一/少数活路）
   Cost       → 这套设计付了什么代价（一句话，别吹）

第 2 步 · 标楼层（每条约束标 L0-L4，判断它可不可以被谈判）：
   L0 物理（网卡/时钟/带宽）｜L1 数学（放大倍数/O(n)）｜L2 语言运行时（GIL/GC）
   ｜L3 领域不变量（版本必须唯一/删除必须终止）｜L4 经济取舍（可谈判，创新住在这里）

第 3 步 · 分解到地板（skill 的分解公理）：
   复杂机制 → 基本数据结构 + 算法。分解不到底 = 没懂，不是系统复杂。

第 4 步 · 挂证据（每条结论标等级）：
   运行时实测 > 源码行 > 手册/文档原文 > 二手 > **结构推断（必须标 unverified）** → **绝不把文档级结论讲成系统级事实**

第 5 步 · 负空间收尾：它**不**保证什么（延迟上限/即时精度/冷启动）——负空间比正空间更能暴露取舍。
```

> **讲解主体 = 两件套（2026-10-13 用户校准——只有推导提纲不算讲解）**：
> 1. **机制走查（怎么运作）**：每个机制必须给**编号走查 + 真实数据**（如"VM-A 发包 → 母机查表 → GRE 封装 Key=3345906 → 对端解封装 → 交付"）；抽象结论不配走查 = 未完成；
> 2. **设计推导（为什么这样）**：问题树（问题→直觉→失效点→被迫设计→代价）；
> 3. **转引纪律**：本篇范围内的机制必须**当场讲透**；"→X 卷"只能用于明显越界的内容，不得用转引掏空讲解。

## 二、拷打环节 = 用 skill 的"问题分类学"出题（每课 3-5 题）

> 补充（skill 原文的两个"底"）：**约束底**（L0-L4 楼层）与**结构底**（数据结构+算法分解）**正交**——一棵完整的树要同时触到两层底。

| 类型 | 模板 | 例 |
|---|---|---|
| 存在 | 为什么要有它？ | 没有对账模块会死在哪？ |
| 破点 | 哪条约束先崩？ | 分区时哪个前提先死？ |
| 反事实 | 反过来行不行？ | 如果 producer 带 key 呢？ |
| 不变 | 哪些在各代之间不变？ | 版本链在 1/2/3 代的同构点 |
| 边界 | 它不保证什么？ | 背压不保证什么？（诚实的短板） |
| 谱系 | 这设计从哪来的？ | visibility timeout ↔ 租约 |
| 等价 | 谁还这么解？ | xDS/kubelet 对照 |
| 成本 | 谁付钱、付多少、多频繁？ | GLOBAL 配置 O(N_SET) 放大 |

## 三、分工与验收

- **我**：给例子、搭问题树草案、讲五段式、出拷打题、核对勘误；
- **你**：闭卷重走问题树（画出/讲出）、写产出物、随时打脸；
- **验收三件套**：① 你能**独立重走**这棵树；② 我**被追问 3 层不倒**；③ 你能说清**负空间**。

## 四、硬纪律（skill 原文提炼，用血换的）

1. **标记概念漂移**——同一个词跨层变义（如"删除"= Release vs Reclaim）→ 拆两行，绝不混用；
2. **归因逐层验证**——内核/JVM/库各归各的权威，禁止一句话混着说；
3. **Baseline before "为什么不 X"**——没有 baseline 的"为什么不用 X"是伪推导；
4. **半答案原则**——被否的方案往往是**子问题**的正解（先问它解决了什么）；
5. **证据边界不放宽**——叙事可以省，机制结论必须挂出处；
6. **修订日志**——每次被打脸：实证核查 → 修正 → 记勘误（本会话已有 2 例：入口链、事故回忆）；
7. **溯因必复核**——"BUT（死法）"是溯因推理，必须跟演绎复核或一次实验，才能升级为结论（skill 原文：every abduction must be followed by a deduction re-check or an experiment）。

## 五、输出风格（2026-10 用户修正：**技术写作体，禁止口语化**）

**体裁**：技术文档/白皮书体——句子平实、术语精确、结论克制。

- **例子先行保留**（AGENTS.md 硬规则）：每个主题先给"具体场景 + 输入→输出"，但**平铺直叙**，不用拟人化故事；
- **类比克制**：每主题 ≤1 个，一句话讲完并标【类比】；类比只建直觉，**不得替代机制**；
- **禁用语**：口语连接词/语气词（吧/呢/嘛）、情绪化词与网络腔（"神奇/零头/撞段/人话"）、拟人化段子（"每家公司都觉得自己…"）、栏目化口语（"人话"列）；
- **术语规则**：首现给定义（全称+一句话）；正文用标准术语；中英混排遵循业界惯例（VPC/Overlay/VLAN/GRE）；
- **标题**：名词短语或书面问句（"为什么 VLAN 不够用"），不写俏皮标题；
- **数字**：带单位、口径、出处；
- 保留：**一次只问一个问题**、每个抽象结论配**编号走查**、实现名只在映射表出现、**证据索引放文末**、每节收尾"**代价一句话**"。

> 一句话标准：**读起来像正式技术文档，而不是博客聊天；既能让非专家看懂，又能直接进入面试表达。**

## 六、产出与落盘

| 产出 | 谁写 | 落盘 |
|---|---|---|
| 课程讲义（从问题树剪出来的正文） | 我 | 讲解时直接输出在对话；成体系后剪成文件 |
| **问题树**（对话深挖 fold 回来，含"断言→证据"表） | 你起草 + 我纠错 | `docs/vpc/qtree-{块号}-{名}.md` |
| 勘误注记 | 我 | 各产出文件文末"勘误注" |

## 七、与学习路线的关系

- 学习路线（`学习路线.md`）= 单元清单（A1-A5 / B1-B5）；**讲解方法 = 本文件**；
- 每个单元 = **1-N 棵问题树**；验收过了再开下一块；
- 深挖课（一个问题追到底）与对照课（同题异解三代/业界）都按同一棵树的规则长；
- 深度分配（skill）：核心域全推导；外围（某协议字段、某工具用法）允许"类比阅读"，但必须**标标签**（"约定/继承"），不得悬空讲。
