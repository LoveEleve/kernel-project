## 0. 术语速查

| 术语 | 含义 |
|---|---|
| **VPCGW** | 公网流量入口/出口："VM 访问公网 → **SNAT**（源 IP 换 EIP）；公网访问 VM → **DNAT**"；同 VPC 内 VM 互通**不经过它**（直接 GRE） |
| **PVGW** | 跨 VPC 的 **GRE 中继**——"**不做 NAT——只做 GRE 中转**"，源/目的 IP 穿越时**不变** |
| **GRE key = vpcId** | 租户隔离的载体；**PVGW 中转时会"换装"**（vpcId_A → vpcId_B） |
| **gwIp（VIP）** | **"VIP 不参与 GRE 封装——只是控制面的概念"**（数据面 outer dst 用物理母机 IP） |
| **HARP** | VPCGW 的主备高可用协议（多路径健康探测）；Master 端口 **65357** / Backup **65358** |
| **切换成本** | "配置同步耗时 + 路由收敛"——HA 的窗口不是毫秒级的小事 |
| **双腿 ZK** | `/TVPC/VPCGW/{vpcgwId}/{vip}` 与 `/TVPC/ZONEVPCGW/{vpcgwId}/{zone}/{vip}`（VPCGW）；`/TVPC/HOST/{hostIp}/` 与 `/TVPC/WHITELIST/PVGWDPDK`（PVGW） |

## ① 它干了什么——两个包的两条"出国路线"

**包 A（10.0.1.71 想上公网）**：VM → 母机 DPDK 查路由（`dst=0.0.0.0/0, nextHop=**VPCGW**`）→ 包到 VPCGW → **SNAT**（`10.0.1.71 → 1.2.3.4`=EIP）→ 出公网；回程 **DNAT** 换回来。

**包 B（10.0.1.71 想找另一个 VPC 的 172.16.1.88）**：母机 A 查路由（`nextHop=**PVGW VIP**, vgwType=3`）→ GRE 封包（**outer: dst=PVGW, GRE key=vpcId_A**）→ 到 PVGW → **解封装 → 查路由（172.16.1.88 属于 vpcId_B）→ 重新封装**（**outer: dst=母机B, GRE key=vpcId_B**）→ 母机 B 解封装 → VM-B。**注意**："源 IP 还是 10.0.1.71，目的 IP 还是 172.16.1.88——**PVGW 没有改变包的内容——只是'打开了一个 GRE 隧道，又包进另一个'**"。

**两条路线的共同点**：VPCGW/PVGW 都是"**边界的翻译官**"——一个翻译"租户 ↔ 公网"（NAT 语义），一个翻译"租户 A ↔ 租户 B"（GRE 重封装语义）。

## ② 链路走查（材料行号）

### 跳 1：VPCGW——公网的闸门（gateway-detail §一）

**位置与部署**（§1.1/§1.2）：夹在 VM 与公网之间；**独立集群——不在母机上**（"每个可用区有多个 VPCGW 实例"）；实例由 **VPCGW Agent** 收配置，监听 **ZK 双腿结构**（`/TVPC/VPCGW/{vpcgwId}/{vip}` + `/TVPC/ZONEVPCGW/{vpcgwId}/{zone}/{vip}`）→ 下发 DPDK：`add_wan(vpcId, vmIp, wanIp=EIP)`（EIP 绑定）+ `add_route(vpcId, dst=0.0.0.0/0, nextHop=VPCGW)`（默认路由）。

**HA——HARP 主备**（§1.3）："正常：GW-Master 处理所有流量，GW-Backup 待命；**Master 端口 65357 / Backup 端口 65358**；切换：Master 故障 → **HARP 协议检测（多路径健康探测）** → Backup 升级 → **配置同步：从 ZK/CKV/LevelDB 拉取全量 VPC 配置** → 切换窗口=**配置同步耗时 + 路由收敛**"。**两个真实 Bug（两个都已修，且都能回课）**：

- "**Bug: feature/3.9.2 修复——切主后 VPC 列表缺失** → `do_switch` 回放 4 类 binlog，**漏了 `VpcBinlog`** → 部分 VPC 在 DPDK 中不存在 → 路由下发失败"——**第 29 课那篇的上下文在此补全**（29 课只记了"回放漏 VPC"，这里给出因果：*回放清单缺一项 → DPDK 里 VPC 都不存在*）；
- "**Bug: CKV 超时** → CKV 建连**无超时** → 断开后**卡住 127s** → 修复：`socket_connect_timeout=3s`"——**超时是分布式系统的安全带**（与第 31 课"60s 堆积"、第 22 课"带重试保存"同一课）。

**数据面操作**（§1.4）：`add_wan(vpcId=3345906, vmIp="10.0.1.71", wanIp="1.2.3.4")` → "**SNAT: 10.0.1.71 → 1.2.3.4；DNAT: 1.2.3.4 → 10.0.1.71**"——一对映射同时立起（有状态 NAT 的两半）。

### 跳 2：PVGW——跨 VPC 的"GRE 换装站"（gateway-detail §二）

**中转原理**（§2.2，两跳换装）——见 ① 的包 B；**关键差异点**：`GRE key=vpcId_A`（第一跳）→ PVGW → `GRE key=vpcId_B`（第二跳）——**同一个包、换了两次"租户标签"**：对母机 A 它是"A 的租户流量"，对母机 B 它是"B 的租户流量"——**PVGW 是租户标签的翻译点**。

**Agent 管理**（§2.3）：`vpc_agent PVGW` 监听 `/TVPC/HOST/{hostIp}/`（"管理每个母机上的 PVGW 路由"）+ `/TVPC/WHITELIST/PVGWDPDK`（"管理哪些 VPC 需要 DPDK PVGW 处理"）；**VIP 语义的精妙**："VIP = gwIp……**VIP 不参与 GRE 封装——只是控制面的概念**"——控制面路由计算用 gwIp 查下一跳，数据面 outer dst 用 PVGW 的**物理母机 IP**（**"控制面的概念"与"数据面的现实"分离**——第 18 课 per-scope version、第 32 课 gwIp 同族的手艺）。

**为什么需要 PVGW**（§2.4）——一个必然性的证明：

```
母机A → 母机B 直接 GRE:
  GRE key = vpcId_A → 母机B 收包 → 查 VPC 配置 → 【vpcId_A 不在本机！】→ 无法转发
解决方案: 母机A → PVGW → 母机B ——"PVGW 同时维护所有 VPC 的路由"
```

**读法**：母机只认识"自己家里"的租户（本地 VPC 配置）；**跨租户的包裹必须在"认识所有租户的中间人"那里换装**——PVGW 就是那个中间人。**同 VPC 内的 GRE 是一跳（已授），跨 VPC 的 GRE 是两跳+换 key（今补）**。

### 跳 3：跨 VPC 三件套——Peering / PrivateLink / CCN（cross-vpc §一/§二/§三）

**① Peering 的控制面六步**（§1.1，以 VPC-A `10.0.0.0/16` ↔ VPC-B `172.16.0.0/16` 为例）：

```
1. 发起：POST /CreateVpcPeer {sourceVpc, targetVpc}
2. INSERT t_vpc_peer (vpcA, vpcB, state=PENDING)
3. 接收方接受 → state=ACTIVE
4. 两侧路由表各加一条：dest=对端CIDR, nextHop=pvgw, vgwType=3
5. Fusion 展开 → 为两个 VPC 的所有 VM 生成转发条目（remoteType=3, remoteVpcId=对端）
6. Broker push → Agent DPDK: add_route → GRE encap to PVGW hostIp
```

**数据面**（§1.2）= 上一跳的 PVGW 两跳换装（同文复述，源/目 IP 不变）。**限制三条**（§1.3）：**同 Region**（跨 Region 用 CCN）／**CIDR 不能重叠**（"否则路由冲突"——第 30 课 BGP 无租户论的 Peering 版）／**N×(N-1)/2 条**——"VPC 数量少时最适用"。

**② PrivateLink——"单向服务消费"**（§2.1 本质区别）："Peering：两个 VPC **完全互通**——所有 IP 可达、**双向**；PrivateLink：**单向**——只暴露**一个服务（VIP:Port）**，对端只能访问这个服务"；控制面：提供者 `CreateEndPointService`（`t_endpoint_service`，**`acceptanceRequired=true`**——连接要**审批**）。

**③ CCN——N² 爆炸的终结者**（§3.1 的算术）：

```
3 个 VPC：Peering 3 条——还行
10 个 VPC：45 条——管理爆炸
100 个 VPC：4950 条——不可行
CCN：所有 VPC 加入 → 自动互通。1 次配置。
```

**路由模型**（§3.2）：CCN 实例关联多 VPC + IDC（"IDC 通过 VPN/专线连接"）→ **自动生成全网状路由**（每个 VPC 的路由表自动添加 `dest=各家 → CCN GW → 目标 (vgwType=4)`）——"**跨 Region 自动选择最优路径——不需要手动配置**"；**数据面**（§3.3）：GRE 到 CCN GW → **查全网状路由** → "GRE encap to VPC-B 的 CCN GW（**跨 Region**）" → 母机 B。（第 32 课六网关表的"**全网状路由 + BGP**"在此展开为数据面动作。）

### 跳 4：EIP/NAT 与 CLB——两条实用速览（eip-nat / lb-gw-ipv6）

**EIP 生命周期五步**（eip-nat §1.1）：`购买（拿到 1.2.3.4）→ 绑定到 VM ENI（VPCGW 配置下发）→ 双向通信 → 解绑（可绑到别的 VM）→ 释放（公网 IP 归还池）`——**数据面在 VPCGW**（§1.2，SNAT/DNAT 已授）；"**弹性**"二字的含义：IP 是**可移动资产**（跟随绑定关系走，而 VM 的私网 IP 不动）——**EIP 就是"给租户一个可携带的世界身份证"**。

**CLB 数据模型**（lb-gw-ipv6 §1.1 `t_service`）：`serviceId / vpcId / vip / vport / proto / type（0=VNET, 1=RNET, 3=REMOTE_VPC）/ **lbType（0=round_robin, 1=least_conn, 2=ip_hash）**`——32 课"type 枚举纠正"的 SQL 原版 + **调度算法字段**（VIP-RS 模型的"怎么选 RS"：轮询/最少连接/哈希——第 8 课 DPVS 的调度器家族在此有配置面同胞）。

## ③ 设计推导（问题树）

**Q1：网关家族的统一元角色，一句话？**
**"世界模型的翻译官"**——每个网关站在两个"网络世界"的边界上，翻译三样东西：**命名空间**（要不要 NAT——IP 语义）、**封装**（GRE/IPsec/隧道）、**路由宇宙**（看见哪些网段、下一跳是谁）。VPCGW 翻译"租户 ↔ 公网"；PVGW 翻译"租户 A ↔ 租户 B"；CCN GW 翻译"多租户 ↔ 多云多 IDC 的全网状"。

**Q2：PVGW 为什么"不做 NAT"？VPCGW 为什么必须做？**
判据是"**边界两边是否共享 IP 命名空间**"：跨 VPC 互通的目标是"两个 VPC 像一个大网"——**两端 VM 要直接互访，IP 必须全程可见**（NAT 会破坏端到端语义、还会和"CIDR 不能重叠"的约束打架）；而出公网时，**外部世界只认公网 IP**——NAT 是唯一选择。**同一条边界法则：能保留端到端语义就不 NAT，必须换身份才 NAT。**

**Q3：Peering → CCN 的进化本质？**
**拓扑学换形**：从"**手工成对的网（N² 条边）**"换成"**中心辐射网（1 个 CCN + N 条边）**"——用户从"管理 N² 个关系"变成"管理 1 个加入动作"。代价是流量汇聚到 CCN GW（材料未展开其容量工程——挂账）。**这是"约束决定架构"（第 30 课）的拓扑版**：规模一过阈值，手工拓扑必须让位给自动全网状。

**Q4：网关的 HA 与母机的 HA 本质差异？**
母机 agent 是"**无状态可重建**"（watchdog 秒级），VPCGW 是"**有状态的边界**"——切主后要"**从 ZK/CKV/LevelDB 拉全量 VPC 配置 + 路由收敛**"，**切换窗口=配置同步耗时+收敛时间**（材料原话）。所以 `do_switch` 的"回放清单漏了 `VpcBinlog`"才致命：**不是慢一点，是部分 VPC 干脆不在 DPDK 里**。**有状态网关的 HA 质量=恢复清单的完整度。**

**Q5：本课补上了"闭环"的哪一块？还缺哪块？**
补上：**南北向（VPCGW/EIP/CLB）与跨域（PVGW/Peering/PrivateLink/CCN）的边界语义+控制面流程+数据面动作**——母机（东西向）+网关（边界）拼合后，"一个包的去向"已能全图解释。**仍缺**：① 各网关的**数据面内部**（NAT 会话表容量/老化、CCN GW 的跨 Region 隧道管理——材料到"GRE encap to 对端 CCN GW"为止）；② **TGW** 专篇尚未见（`vip_tgw` 只见于资源清单）；③ VPNGW/DCGW 细节待 35 课混合云篇。

## ④ 对照卡：网关家族（本课四员）

| 边界 | 网关 | 语义 | 数据面动作 | HA/特性 |
|---|---|---|---|---|
| VPC ↔ 公网 | **VPCGW** | 换身份（NAT） | `add_wan`（SNAT+DNAT 一对）+ 默认路由 | **HARP 主备**（65357/65358）+ 配置同步窗口 |
| VPC A ↔ VPC B | **PVGW** | **不换身份**（GRE 换装） | 解封装→查路由→再封装（key 换 vpcId） | 多实例 LB；**VIP 只是控制面概念** |
| 多 VPC/多 IDC | **CCN GW** | 全网状自动化 | 查全网状→跨 Region GRE 到对端 CCN GW | **1 次配置**；自动选最优路径 |
| 服务消费 | **PrivateLink** | **单向暴露**（VIP:Port）；**跨 Region ✅** | **PL GW GRE 中转**（§四表实证） | **acceptanceRequired 审批**；安全性="只暴露一个服务" |

**材料自己的"三种方式对比表"**（§四，全文照搬）：

| | Peering | PrivateLink | CCN |
|---|---|---|---|
| 互通范围 | 2 VPC 双向 | **1 服务单向** | N VPC + M IDC 全网 |
| 路由管理 | 手动加路由 | 消费者侧 VIP | **CCN 自动分发** |
| **跨 Region** | ❌ | ✅ | ✅ |
| 安全性 | VPC **完全暴露** | **只暴露一个服务** | VPC 完全暴露 |
| vgwType | 3（PVGW） | 通过 endpoint 路由 | 4（CCN） |
| 数据面 | PVGW GRE 中转 | **PL GW GRE 中转** | CCN GW GRE 中转 |
