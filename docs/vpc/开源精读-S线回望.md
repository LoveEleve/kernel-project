## 一、换代主线——一张图

```
一代（Gen1/2）                二代（过渡代际）              5.0（Gen3）
─────────────────────────────────────────────────────────────────
ZK 树 = 真相 + 分发管道        上游仍是分区 ZK（不动）         Kafka binlog + tRPC Stream
"中心推 + 端侧 watch"          下游先换：心跳拉 + 记账         拆微服务（10 子项目）
agent_base（工具包）           agentos（应用框架+微内核）      framework（微内核+默认全套器官）
nfv-proxy（转发者）            agent-broker（账房）            fusion（中转+快照+对账+清理）→ broker → host-agent
30-40 分钟重注册（第 4 课）     秒级（SQLite/内存版本）         秒级（LevelDB + quick_restart 默认开）
无系统化对账                    端侧报案（UpdateHostDiff）      三层对账（inspector / reconcile / base 标准件）
```

三条最关键的话（均有出处）：

1. **"把一棵树，换成了一队流水线"**（第 18 课综合问）——ZK 不是被删掉的，是被整个体系**分摊**掉的（分发材质 / 记账 / 对账 / 清理各领一份）；
2. **"上下游异步换代"**（第 16 课）——迁移哲学：**在稳定的上游之下，换掉整个下游**（先把网元侧换掉，配置源换新留给 5.0）；
3. **"机制先在这里长大"**（第 26 课）——S 线读到的一切（选举/队列/租约/对账/SDK），最终都在 `vpc-base` 里以库的形态**回收**（六个服务共用一份修复红利）。

## 四、怎么用这份回望

1. **面试向**：先背"三种换代的一句话"（一棵树→流水线 / 上下游异步 / 机制先长大），再按"机制回环总表"横向串（面试官问哪个机制，都有一条跨代时间线可讲）；
2. **复盘向**：任何一次线上问题，先查"错比停危险"三重奏与"恢复的阶梯"两行——它们覆盖本系统绝大多数故障处置决策；
3. **写作向**：审查账（§三）是一份现成的"配置类系统写作避坑清单"。
