# 02 共识与 Raft：三个节点挂了一个，为什么还能正常工作？

> 定位：分布式理论快读第 2 篇（面试核心）。**例子先行**：3 节点集群的选主与日志复制。
> 对照：权威大纲 `01-分布式理论/04-paxos-core + 05-multi-paxos-raft`。
> 已学对照：Nacos 持久实例（JRaft）、Nacos 集群（RaftServer:7848）——本篇是它们的"为什么"。

---

## 一、它干了什么：一个例子

**场景**：3 个节点的 Raft 集群（etcd/Nacos JRaft 同款模型），复制一条日志"x=1"。

```
正常：Leader(A) 收到写 → 复制给 B/C → 多数派(≥2)确认 → 提交 → 三节点都应用 x=1

故障：A 宕机
  → B/C 心跳超时 → 发起选举（任期+1，拉票）
  → 拿到多数派（2/3）选票者成为新 Leader（如 B）
  → 客户端改连 B → 服务继续（集群整体仍可用）

危险：网络分区把 A 和 B/C 隔开
  → A 以为自己还是 Leader（收不到 B/C 的回复）
  → 但 A 的写入拿不到多数派 → **永远无法提交**（旧 Leader 不能造成双写）
```

**它干的事一句话**：共识协议让多个副本对"同一个操作序列"达成一致——**多数派同意即提交**，少数派/旧主无法单独改变结果。

---

## 二、为什么需要它：主从复制为什么不够

| 方案 | 问题 |
|---|---|
| 单机 | 挂了就没了 |
| 主从（异步） | 主挂丢数据；**谁是新主**靠人工/脚本，可能双主（脑裂） |
| 主从（半同步） | 仍不能自动选主；一致性与可用性难兼顾 |
| **共识协议（Raft/Paxos）** | 自动选主 + 多数派提交 + 旧主安全约束 |

**本质**：复制状态机（Replicated State Machine）= **一个确定的顺序 + 多数派持久化**。共识协议解决"这个顺序怎么定"。

## 三、怎么做：quorum + Raft 三件套 + 脑裂

### 3.1 quorum（多数派）——一切安全的根

- `quorum = ⌊n/2⌋ + 1`：3 节点 = 2，5 节点 = 3；
- **任意两个多数派必有交集** → 新 Leader 一定见过已提交的日志 → 不会"丢已提交数据"；
- 容忍故障：3 节点容 1、5 节点容 2（这就是 Nacos 推荐 3 节点的原因，nacos-lab A-07）。

### 3.2 Raft 三件套（面试重点）

| 机制 | 规则 | 解决什么 |
|---|---|---|
| **选举** | 心跳超时 → 任期+1 → 拉票 → 多数派当选；每任期每节点只投一票 | 自动选主、避免双主 |
| **日志复制** | Leader 追加 → 复制 → 多数派确认 → 提交；**日志匹配性质**：相同 index+term 的日志内容相同 | 副本一致 |
| **安全约束** | ① 选举限制：候选人日志必须"至少一样新"；② 提交限制：Leader 只能提交当前任期日志 | 旧日志/旧主不能覆盖已提交 |

### 3.3 脑裂（split-brain）：分区时会发生什么

```
分区: [A] | [B C]
- A 无法提交（拿不到多数派）→ 客户端超时（牺牲可用性，保一致性 → CP）
- B/C 选新主，继续服务
- 分区恢复：A 发现更高任期 → 退回 Follower，**用新主的日志覆盖自己未提交的日志**
```

**结论**：Raft 是 **CP** 系统——分区时少数派不可用，但不会双写。

### 3.4 Paxos 一句话（面试够用版）

Basic Paxos：Prepare（拿多数派承诺）→ Accept（多数派接受一个值）；**两个多数派交集**保证"只有一个值被选定"。Raft = Multi-Paxos 的工程化（强 Leader + 日志连续性 + 任期），牺牲部分自由度换取可理解性。

**工程对照**：
- **Nacos 持久实例**：JRaft（`PersistentClientOperationServiceImpl`，Raft log + snapshot，nacos-lab D-10）；
- **Nacos 配置/临时实例**：**不用** Raft——Config 走 AsyncNotify（共享 MySQL），临时实例走 Distro（AP 反熵）；
- etcd/K8s：Raft 做元数据存储。

## 四、值不值得深挖 & 面试问答

**值不值得**：Raft 选举/日志复制/脑裂必问（🔴）；Paxos 细节、ZAB/EPaxos/变种翻篇（🟡→🟢，知道定位即可）。

**Q1：3 节点挂 1 个为什么还能写？**
quorum=2，剩 2 个仍构成多数派，可继续选主与提交。

**Q2：分区时旧 Leader 能继续写吗？**
不能提交（无多数派），只能接受写入到本地日志；恢复后被新主覆盖——这是防双写的核心。

**Q3：Raft 和 Paxos 什么关系？**
Raft 是 Multi-Paxos 的工程化变体：强 Leader、日志只追加、任期约束；更易实现与解释。

**Q4：为什么 Nacos 配置中心不用 Raft？**
Config 用"共享 MySQL + AsyncNotify 通知拉取"就够（数据源是 DB，不是内存副本）；Raft 只用于 Naming 持久实例（内存数据的强一致复制）。
