# L3-06 — 评论体系：楼中楼模型与游标分页

> **定位**：L3 业务域链路第 6 篇（P0 缺口：58-评论体系）。四段式：**时序 → 决策 → 组件映射 → 拷打**。
> **依据**：xhs-project 评论代码（CommentService/Mapper）+ 58-评论体系 + O-Comment-1/C2/R1 修复记录。

---

## 一、它干了什么：模型 + 读写删三链

**模型（`t_comment` 两级树）**：
```
parent_id = 0 → 一级评论；parent_id = 一级 ID → 楼中楼子评论
reply_to_id → "回复了谁"（@ 语义，不做无限嵌套）
字段：note_id/user_id/parent_id/reply_to_id/content/like_count/deleted
```

**写链（createComment）**：
```
事务落库 → afterCommit 内：① MQ 发评论事件（计数/通知下游）② delayDoubleDelete 清 COMMENT_COUNT
【修复C2】MQ 必须在 afterCommit 内发——事务回滚后通知已发出是经典事故
```

**读链（一级列表 + 预加载）**：
```
getCommentList(noteId, lastId, pageSize)：游标分页（note_id + parent_id=0 + id<lastId 倒序）
每条一级预加载前 3 条子评论；pageSize 上下限钳制；lastId 缺失取最新
```

**删链（deleteComment）**：
```
逻辑删除（deleted 标记 + 幂等判重）→ afterCommit 发 UNCOMMENT 事件（批量：totalDeleted 条合成 1 条，避免 N 条 MQ）
→ 计数回退（counter 服务）→ O-Comment-1：COMMENT_LIST 死缓存已移除（列表直查 DB 不回填，delayDoubleDelete 纯开销）
```

---

## 二、设计决策

| 决策 | 为什么 |
|---|---|
| **两级不无限嵌套** | 查询/渲染复杂度指数上升；`reply_to_id` 足够表达"@谁"；行业主流也是两级 |
| **游标分页（id<lastId）** | offset 深翻全表扫；游标走主键索引稳定 + 新评论插入不影响已翻页（无重复/跳过）；代价是不能跳页 |
| **afterCommit 发 MQ** | 事务回滚后通知已发出 = 幽灵事件（C2 教训）；提交后发是铁律 |
| **UNCOMMENT 合并事件** | 批量删除发 N 条 MQ 是浪费；1 条带计数事件 + 幂等消费 |
| **O-Comment-1 死缓存移除** | COMMENT_LIST 读路径直查 DB 从不回填 → delayDoubleDelete 纯开销；保留 COMMENT_COUNT（有读缓存才删） |
| **计数 Redis 权威 + 对账** | 写评论发事件 → counter 幂等 +1；DB 异步落库；对账 Job 收敛（11/18 题同源） |
| **热点评论** | 计数原子操作 + Buffer 批量落库；正文写 DB（note_id 索引）；读走游标+Redis |

## 四、拷打问题

1. **"为什么不做无限嵌套？"** 查询渲染复杂度 + 收益低；两级 + reply_to_id 足够；行业主流。
2. **"游标分页的坑？"** 需稳定排序键（id 单调）；新插入不影响已翻页；不能跳页（业务可接受）；lastId 缺失取最新。
3. **"评论数怎么保证准？"** 写发 MQ 事件 → 计数幂等 +1；Redis 实时、DB 落库；对账收敛；重复投递 msgId 去重。
4. **"删评论计数怎么回退？"** 逻辑删除 + 判重（已删不重复扣）+ UNCOMMENT 合并事件；删除与计数靠事件最终一致 + 对账。
5. **"MQ 放事务外还是 afterCommit？"** 必须 afterCommit（C2 教训：回滚后通知已发是幽灵事件）。
6. **"热点笔记评论怎么扛？"** 读游标+Redis；写原子+Buffer；正文 DB（note_id 索引分片）。

## 五、话术

> "评论做两级：一级加楼中楼，parent_id 标识所属一级、reply_to_id 标识回复谁，不做无限嵌套。列表用游标分页 id 小于 lastId，深分页不退化。写评论事务提交后发 MQ 事件给计数和通知，删除是逻辑删除加幂等判重加计数回退；评论数 Redis 权威、DB 兜底、对账收敛。踩过的坑：MQ 放事务外导致回滚后通知已发出，现在全放 afterCommit；还有个死缓存，列表直查 DB 从不回填，延迟双删纯属开销，直接移除了。"
