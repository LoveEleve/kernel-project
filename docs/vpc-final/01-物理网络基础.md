# 01 · 物理网络基础——不懂云之前，先弄懂"物理世界的网络"

> 本篇目标：把"两台服务器怎么互通"这件事彻底讲透——后来 VPC 的每一个概念，都是本篇概念的"虚拟化影子"。

## 开篇：一个机房的日常

张三有个小机房，里面两台服务器：A 和 B。他要让 A 能 ping 通 B。

网络工程师给两台机器各配了地址：`A = 10.0.0.10`，`B = 10.0.0.20`，中间插了一台交换机（交换机和路由器是什么，§2.1 就讲，先看走向）。ping 通了。完事。

听起来没什么可讲的？**但"配个地址就能通"这件事背后，藏着整个网络世界的五个基本功**——IP、子网、MAC/ARP、网关/路由、NAT。这五个词，后来会以"虚拟化"的形态**原封不动地**出现在 VPC 里。所以在碰云之前，我们先把它们在物理世界的样子看个够。

## 0. 术语速查（本篇会逐一展开）

| 术语 | 一句话 | 生活比喻 |
|---|---|---|
| **IP 地址** | 网络里的门牌号（如 10.0.0.10） | 楼号+房号 |
| **网卡（NIC）** | 服务器的"收发口"——每个口一个 MAC | 门上的收发小窗 |
| **交换机（Switch）** | 楼内的"接线板"——**只认 MAC**（二层） | 楼里的内部信箱分拣 |
| **路由器（Router）** | 楼与楼之间的"大门+路牌"——**认 IP**（三层） | 园区门口的指路亭 |
| **子网 / 掩码 / CIDR** | 把一片地址切成"楼栋"的刀法（如 10.0.0.0/24） | "从 10.0.0.1 到 10.0.0.254 归我们楼管" |
| **MAC 地址** | 网卡的物理身份证（如 52:54:00:e8:f1:3c） | 收件人的手印 |
| **ARP** | 同楼里"喊话"问对方 MAC 的协议 | 在楼道喊："10.0.0.20 是谁？" |
| **网关** | 出口——出门找它 | 小区大门 |
| **路由表** | "去哪里、交给谁"的清单 | 大门旁的路牌 |
| **NAT** | 出门时把私家门牌换成公家门牌 | 前台代收代发 |
| **私网地址** | 只能内部用的门牌段（10.x / 172.16–31.x / 192.168.x） | 小区内部房间号 |

## ① 第一个例子：两台服务器互 ping——两种走法

同样是 `A ping B`，**两个地址的关系不同，包的走法完全不同**。

### 走法一：同子网（10.0.0.10 → 10.0.0.20）

```
【第 1 步】A 发现 B 和自己在同一个"楼栋"（同子网，后面解释怎么判断）
【第 2 步】A 在楼道喊话（ARP）："谁是 10.0.0.20？报上你的 MAC！"
【第 3 步】B 应答："我是，我的 MAC 是 52:54:00:e8:f1:3c"
【第 4 步】A 把包直接封给对方 MAC，交给交换机
【第 5 步】交换机按 MAC 把包转发给 B —— 全程没有路由器什么事
```

> 关键认知：**同子网内，包是"喊名字"送到的（MAC），IP 只是用来找到名字的线索。**

### 走法二：跨子网（10.0.0.10 → 10.0.2.5，另一台服务器）

```
【第 1 步】A 发现 10.0.2.5 不在自己楼栋（10.0.2.x 是别处）
【第 2 步】A 把包交给自己的"大门"——网关（子网 10.0.0.0/24 的网关是 10.0.0.1）
【第 3 步】路由器收下包，翻自己的路牌（路由表）："去 10.0.2.0/24？往那个口送"
【第 4 步】下一台路由器/交换机接力，直到目标所在的楼栋
【第 5 步】最后一跳再"喊一次名字"（ARP 找到 10.0.2.5 的 MAC），投递完成
```

> 关键认知：**跨子网，包是"走网关、看路牌"送到的（路由）。**

**两句话记住**："同楼喊名字，跨楼看路牌。" 后面所有的网络概念——包括 VPC——都在这条主轴上生长。

## ② 拆开看：三件硬件 + 五个基本功

### 2.1 先认三件硬件：网卡、交换机、路由器

物理网络的舞台上只有三件主角：

```
【网卡（NIC）】——服务器的"收发口"
  每台服务器至少一张网卡，每个口出厂自带一个 MAC 地址（2.4 节会用到）
  包从这个口出去、也从它进来

【交换机（Switch）】——楼内的"接线板"
  同一栋楼（同子网）的机器都插在它上面
  它只干一件事：按 MAC 把帧从"来"的口转到"去"的口
  ——不认 IP。所以"同楼通信"它全包了（走法一）

【路由器（Router）】——楼与楼之间的"大门 + 路牌"
  连接不同的楼栋（不同子网）
  它认 IP：翻自己的路由表，把包往下一跳送（走法二）
  顺带一词：楼里的"大门"（网关）往往就是一台路由器的接口
```

两个"别被绕晕"的补充：

- **三层交换机** = 兼职了路由器工作的交换机——名字是历史包袱，判断只看一条：**它认 MAC 还是认 IP**；
- 家用的"路由器"其实是个**四合一盒子**：路由器 + 交换机 + 无线热点 + NAT 全在里面——所以它既能当"大门"，又能当"接线板"。

### 2.2 IP 地址——门牌号

`10.0.0.10` 是 32 位二进制（IPv4）写成"点分十进制"的样子：每一位（0–255）对应 1 字节。**门牌号的唯一性只在"自己的地盘"里要求**——这给后来 VPC 的"不同租户可以撞号"埋下了伏笔。

**私网地址**：全世界约定留了三段"小区内部号"，不上公网直接用：

```
10.0.0.0     ~ 10.255.255.255      （大园区，云上最常用——所以你看腾讯云 VPC 都是 10.x）
172.16.0.0   ~ 172.31.255.255
192.168.0.0  ~ 192.168.255.255     （家用路由器最常见——192.168.1.1）
```

**为什么要留私网段？** 因为公网门牌是稀缺资源（IPv4 只有约 43 亿个）。如果每台设备都占一个公网号，早就发完了。解法是"内部用私号，出门再换公号"——这就是后面要讲的 NAT。

### 2.3 子网与 CIDR——怎么切"楼栋"

`10.0.0.0/24` 这个写法叫 **CIDR**，`/24` 表示"前 24 位是楼栋号，剩下的归住户"：

```
10.0.0.0/24 的范围：10.0.0.0 ~ 10.0.0.255（共 256 个地址）
  10.0.0.0   ← 网络号（楼栋本身，不能给住户）
  10.0.0.1   ~ 10.0.0.254  ← 可用的住户地址
  10.0.0.255 ← 广播地址（喊"全楼注意"用的）
```

**子网掩码**是同一件事的另一种写法：`/24` = `255.255.255.0`——"前三段相同 = 同楼"。

**判断同楼的方法**：把两个 IP 分别和掩码做"与"运算，结果相同就是同子网：

```
10.0.0.10 与 255.255.255.0 = 10.0.0.0
10.0.0.20 与 255.255.255.0 = 10.0.0.0   → 同子网 ✓
10.0.2.5  与 255.255.255.0 = 10.0.2.0   → 不同子网 ✗（所以走网关）
```

> 切多大由你定：`/24` 给 256 个地址，`/16`（如 `10.0.0.0/16`）给 65536 个——一个 VPC 常用 `/16`，内部再切若干 `/24` 子网。**"地址池切分"从这一刻起就是网络设计的核心动作。**

### 2.4 MAC 与 ARP——同楼喊名字

每张网卡出厂自带一个 **MAC 地址**（形如 `52:54:00:e8:f1:3c`）——真正的"物理身份证"。**ARP** 是"把 IP 问成 MAC"的喊话协议（走法一里的第 2-3 步）。

为什么搞两层（IP 一层、MAC 一层）？**因为"楼栋"内和"楼栋"间的找路方式本就不同**：
- IP（三层）：**决定去哪栋楼**——可以跨过无数路由器，端到端不变；
- MAC（二层）：**决定在同一栋楼里交给哪只手**——每过一跳就换一对。

同楼不喊名字不行（IP 不知道接到哪个口）；跨楼每跳都要重新喊（下一栋楼谁认识你旧 MAC？）——**这就是"三层寻址、二层投递"的分工**。记住这个分工，后面 VPC 里的 `GWMAC`（网关 MAC 代理）你一看就懂。

### 2.5 网关与路由表——楼与楼之间的路

**网关**：本子网的"大门"——不知道往哪走时，包都交给它（默认网关）。约定俗成，子网的第一个可用地址常被当网关用（如 `10.0.0.1`，腾讯云子网保留 IP 的规则与此同源——后面会讲）。

**路由表**：每台有路由能力的设备（含服务器自己）都揣一张"去哪里、交给谁"的清单。以服务器 A 为例：

```
目标网段          下一跳
10.0.0.0/24      直连（同楼，自己送）
0.0.0.0/0        10.0.0.1   ← 【默认路由】其余一切，都交给大门
```

（路由器上的表条目更多——"某个网段交给某个专线口"之类，但骨架与这张一模一样。）

`0.0.0.0/0` 读作"所有地址"——**默认路由**。出门打不到具体路牌，就走它。

> 当两条规则都能匹配时，选"更具体"的那条（前缀更长者优先）——这叫**最长前缀匹配**，先去理解直觉：**"楼下快递柜"规矩胜过"全城快递规则"。** 系统的完整规则留到 `75-路由体系.md` 展开。

### 2.6 NAT——前台代收代发

私网门牌出不了门（公网不认），怎么办？**出门前，网关当"前台"，把私号换成公号**：

```
家里三个设备都用 192.168.1.x（私网）
    ↓ 路由器（前台）
对外只用一个公网 IP（比如 1.2.3.4）

【出方向 SNAT】设备号 192.168.1.5:54321 → 换成 1.2.3.4:随机端口
【回方向 DNAT】回来的包看端口认得是哪台 → 换回 192.168.1.5
```

- **SNAT**（源地址转换）：出方向换"寄件人门牌"；
- **DNAT**（目的地址转换）：回方向（或公网主动访问内网时）换"收件人门牌"。

家里路由器默默干的事，正是云上 **NATGW / VPCGW（EIP）的雏形**——只不过云上的"前台"要给几百万租户排队、记账（conntrack）、还要扛几十万并发。**"换门牌"三个字，后面 `68-VPCGW与EIP·NATGW.md` 会用一整篇讲它的工业形态。**

## ③ 为什么控制面工程师要先懂这些

因为你以后每天在做的事，就是**把这五个基本功"虚拟化"**：

| 物理世界 | VPC 里的虚拟化影子 | 去哪深挖 |
|---|---|---|
| 门牌号（唯一） | **虚拟门牌**——不同 VPC 可以撞号（张三李四都用 `10.0.0.0/24`） | `03-Overlay与封包原理.md` |
| 楼栋（子网） | **虚拟子网**——租户自己切，网关是保留 IP 里的约定 | `78-网络对象家族.md` |
| 喊名字（ARP） | **GWMAC 代理**——网关替全楼应答"名字" | `81-场景：同VPC互访.md` |
| 路牌（路由表） | **下发的路由**——控制面把每个租户的路由算好推给每台母机 | `75-路由体系.md` |
| 前台（NAT） | **NATGW/EIP**——百万租户共享公网资源；SNAT/DNAT 双击 | `68-VPCGW与EIP·NATGW.md` |

再往前一步：物理世界的交换机为什么不够用？**多租户**。张三和李四都想用 `10.0.0.0/24`——传统解法是 **VLAN** 给每租户贴个隔离标签，但 **VLAN 最多 4096 个**（材料：`00-background/01-vpc-basics.md` §1.2），腾讯云有几百万租户——**4096 对几百万，差了三个数量级的隔离能力**。而且 VLAN 是二层隔离，跨地域（广州到北京）根本使不上。这就是 VPC 必须诞生的第一性原因——**下一篇的主题**。

## ④ 你该带走的

**一句话**：物理网络回答"包怎么找路"——**同楼喊名字（MAC/ARP）、跨楼看路牌（网关/路由）、出门换门牌（NAT）**；而 VPC 的全部魔法，都只是把这三件事**虚拟化**了一遍。

**带走四题**（自测，答案都在本篇里）：
1. `10.0.3.7/24` 和 `10.0.3.200/24` 同子网吗？`10.0.4.1/24` 呢？——判断依据是什么？
2. 为什么 MAC 每过一跳就换、IP 却端到端不变？如果反过来会怎样？
3. 家里路由器没配任何"路由表"页面，为什么手机也能上任何网站？（提示：默认路由 + NAT）
4. 交换机认什么、路由器认什么？拿到一台"三层交换机"，你用什么**一句话**判断它此刻在干谁的活？
