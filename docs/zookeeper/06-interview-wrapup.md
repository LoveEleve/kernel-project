# 06-面试收口：五篇回链与陷阱

## §0 它干了什么（例子先行）

本篇零新概念，三张清单收口：

```
① 五篇要点回链 ② 高频坑速查 ③ 话术（自建）+ 终检
```

## §1 五篇要点回链

| 篇 | 一句话考点 | 回链 |
|---|---|---|
| 01 | 四件套；节点四类型；临时+顺序黄金组合 | 01 |
| 02 | 两幕（恢复选主/广播复制）；zxid=epoch+counter；ZAB≈Raft | 02 |
| 03 | 可靠性四跳；一次性 watch 是设计；羊群效应解法 | 03 |
| 04 | Curator 三层；recipes=协议写成类；可重入锁 | 04 |
| 05 | 选型三问；窗口性不可用 vs 脏读窗口 | 05 |

**追问秒答 4 条**：临时节点谁删→会话超时副作用（01/03）；watch 为什么一次性的→服务端零订阅状态（03）；ZAB 和 Raft→同一件事两种讲法（02）；ZK 和 Nacos 怎么选→三问定站位（05）。

## §2 高频坑速查

| # | 坑 | 正解 |
|---|---|---|
| 1 | 原生 watch 忘续订 | 触发即失效——重注册或用 Curator Cache（03/04） |
| 2 | 所有人 watch 同一节点 | 羊群——只 watch 前一个（03） |
| 3 | 选主用持久节点 | 宕机不自动摘——必须临时（01/03 四跳） |
| 4 | sessionTimeout 过短 | GC 停顿即过期——10~30s（03） |
| 5 | 高频抢锁用 ZK | 每次抢=一次 CP 写——不经济（05） |
| 6 | 拿 ZK 当大规模注册中心 | 十万实例写风暴——AP 系（05/Nacos 04） |
| 7 | 手写锁不重入 | InterProcessMutex 有、手写常漏（04） |

## §3 话术（按拷打口径自建）

> "ZooKeeper 我按四件套讲：强一致 znode 树+会话+一次性 watch+ZAB。临时顺序节点是锁和选主的黄金积木——进程死→会话超时→临时节点自动删→watch 通知下一个，四跳自愈。底层 ZAB 两幕：恢复幕按 zxid 选主（epoch 防旧主），广播幕提案加多数派 ACK 复制——和 Raft 同构。工程上用 Curator（InterProcessMutex/LeaderLatch），把一次性 watch 的续订和重连补节点都包了。选型上它是 CP：协调器站强一致，代价是选举窗口写阻塞——所以大规模注册选 Nacos 这类 AP，选主/锁这类'决策必须唯一'的场景才是 ZK 的主场。"
