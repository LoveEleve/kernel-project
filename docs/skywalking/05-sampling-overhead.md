# 05-采样与开销：实测口径

## §0 它干了什么（例子先行）

同一台机器、同一条压测命令，agent 开关各两轮：

```
OFF：7,774 / 7,952 RPS（均值 7,863）      RPS=每秒请求数
ON ：7,209 / 7,668 RPS（均值 7,439）
结论：吞吐开销 ≈ 5.4%；P50 延迟 +0.41ms（+17.6%）   P50=一半请求的延迟中位数
```

- **它干了什么**：回答"挂 agent 到底贵不贵"——**用同一方法测出来的数字才可比**。
- **本篇回答**：采样参数怎么定？5.4% 怎么测出来的？为什么"口径纪律"比数字本身重要？

## §1 掌握卡（3 条）

1. **采样默认很保守**：`sample_n_per_3_secs=1`（每 3 秒 1 个 trace）——生产常态；全采样 `SW_AGENT_SAMPLE=-1`（压测/全链路演示，注意开销）；关闭 `SW_AGENT_DISABLED=1`（追问4 三档）。
2. **开销实测（K14④原文口径）**：wrk 同机同参数、ON/OFF 两轮交替——吞吐 **5.4%**、P50 +17.6%；成本来源=字节码增强（每次调用多几跳）+ 异步上报队列（内存/序列化）。
3. **口径纪律是头号教训**（陷阱7）：历史基线 4,871 RPS 是"无 agent"且**另一套方法与缓存状态**——**不可直接比**。任何性能数字必须标注"agent 开/关 + 方法"双口径。

## §2 采样三档与选型（追问4）

| 档 | 参数 | 何时用 |
|---|---|---|
| 默认 1/3s | 不配 | 生产常态——量与存储可控 |
| 全采样 | `SW_AGENT_SAMPLE=-1` | 压测对齐、全链路演示、排障临时开——**开销上升，用完关回** |
| 关闭 | `SW_AGENT_DISABLED=1` | 性能基线测量、问题隔离 |

**和 Tracing 07 的呼应**：SW agent 采样（每 3 秒窗口计数放行 1 条）与 Brave 侧 `sampling.probability`、OAP 侧 `rate`（万分比）是**三个独立闸门**——Tracing 07 讲过后两者，本篇补第三处。多系统叠加时记住：**全开=三重采样成本**。

## §3 实测方法为什么可信（方法论一句）

- 同机同命令（`wrk -t4 -c32 -d30s`）；
- **ON/OFF 各两轮交替**（防单轮漂移）；
- 报告并列历史基线并**明确不可比的原因**——口径纪律的正面示范。

## §4 边界（一句话翻篇）

- 开销构成的细粒度拆解（CPU vs 内存 vs GC）→ 报告 `skywalking-overhead-20260918.md` 用时查。
- 采样率与存储预算的量化表 → OAP 侧 TTL/容量话题（06）。
- 业务侧 MDC/logback 开销 → Tracing 05（已封卷）。
