## 一、速记卡（一页纸）

1. **B+ vs LSM**：读多点查事务 → B+（InnoDB）；写多追加 → LSM（RocksDB）；搜索 → 倒排（专用）。
2. **分区**：Hash（点查 O(1)，范围全扫）vs 范围（范围友好，热点倾斜）；一致性哈希+虚拟节点解决扩容迁移。
3. **复制**：主从（单主串行，RTO/RPO 诚实标注）vs 多主/无主（永远可写，冲突后置）。
4. **N/R/W**：R+W>N 即 quorum-like；常见 (3,2,2)；W=1 永不拒写。
5. **GFS**：单 master（元数据内存）+ 64MB chunk + 租约串行 + record append（at-least-once 原子）。
6. **Bigtable**：(row,column,time) 三维 + tablet + 三级定位 + memtable/SSTable + Chubby。
7. **Dynamo**：去中心对称 + 向量时钟 + sloppy quorum/hinted handoff + Merkle 反熵。
8. **OceanBase**：单点写 → 等价节点+Paxos → 日志流解耦（三级跳）；TPC-C 707M。
9. **一致性谱系**：线性 > 顺序 > 因果 > 读写 > 单调读 > 最终——按业务选，不升格。
10. **正确性边界**：共识/复制只保证"日志一致"，业务正确还要幂等/对账/fencing。

## 二、5 道题（意图 + 主线 + 追问链）

### Q1 "B+树和 LSM Tree 的适用场景？"（意图：存储引擎选择能力）

**主线**：B+ 原地更新 → 读优 O(log N)（点查/范围/事务）；LSM 追加+后台合并 → 写优（顺序写吞吐）。
选型：InnoDB/MySQL（OLTP）vs RocksDB/LevelDB（写密集）vs 倒排（搜索专用，不在二选一里）。
**追问链**：LSM 读慢怎么办？→ Bloom + block cache + compaction 减层。写放大谁高？→ LSM（多层重写）vs B+（页分裂）。
**危险信号**：只会背定义；说不出三放大（写/读/空间）。

### Q2 "一致性哈希如何解决节点增删的数据迁移？"（意图：分布算法理解）

**主线**：环上只影响邻居（新增从后继接管部分，删除交给后继）——对比取模的全量迁移。
进阶：虚拟节点（均匀+异构+故障打散）；Dynamo 策略 1→3 演进（成员信息小 3 个量级 + 文件级搬迁）。
**追问链**：热点 key 怎么办？→ 热 key 不靠分区（靠缓存/拆分）。虚拟节点数怎么定？→ 按容量/迁移粒度。
**危险信号**：只画环说不出虚拟节点；不知道策略演进。

### Q3 "GFS 为什么选择原子追加而不是随机写？"（意图：论文设计理解）

**主线**：追加写幂等（失败重试安全）+ 工作负载 99% 追加（实测覆盖写 <0.05%）→ record append（at-least-once 原子，应用 checksum/去重）。
**追问链**：租约干什么？→ primary 定序（全局串行）。master 存什么？→ 元数据内存（<64B/chunk），位置 poll 不持久。
**危险信号**：把 GFS 当通用文件系统背；说不清 defined/consistent 区别。

### Q4 "Dynamo 是如何处理并发冲突的？"（意图：去中心化设计理解）

**主线**：向量时钟检测（祖先覆盖/并发并存）→ 读返回多版本 → 应用合并收敛（购物车范例）；写带 context 声明基版本。
**追问链**：N/R/W 怎么配？→ (3,2,2) 常见；W=1 含义？→ 永不拒写。临时 vs 永久故障？→ hinted handoff vs Merkle 反熵。
**危险信号**：以为最终一致=随便丢；说不出 sloppy quorum。

### Q5 "OceanBase 为什么从单点 UpdateServer 演进到 Paxos 多副本？"（意图：架构演化思维）

**主线**：业务从 90% 读（单点写够用）→ 读写均衡 + 高可用要求 → 等价节点 + Paxos（v1.0-3.0，TPC-C 707M）→ 小租户降本（v4.0 日志流解耦）。
**追问链**：单点写的好处？→ 事务/并发/一致性检查简单。v4.0 解决什么？→ 分片数≠日志流数（小应用不交日志税）。
**危险信号**：只背组件名；说不清每次演进的业务动因。
